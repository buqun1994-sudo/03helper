# Task Closeout

## 1. 输入

1. 当前任务目标和完成标准。
2. 本轮实际改动及用户已有改动。
3. 已执行的本机验证、设备 smoke 和客观阻断。
4. 用户是否已反馈主测结果，以及是否明确授权提交、推送或发布。

## 2. 步骤

1. 读取根 `AGENTS.md`、`docs/testing/验证矩阵.md` 和 `docs/progress.md`。
2. 执行 `git status --short --branch`，区分本轮改动与已有改动。
3. 汇总实际改动，必要时更新产品、架构、验证、安全或进度文档。
4. 复用本轮有效本机验证；Android 工程行为改变后，在本机上下文和显式测试设备可用时，构建并核对最新 Debug APK，然后执行保留数据覆盖安装。覆盖安装是交付用户测试的前置，不等同于运行 smoke。
5. 安装后只运行已有、稳定、预计单条不超过 5 分钟且无破坏性动作或未具备外部发布前置的最小 smoke；更复杂的真实网络、WebView、车机写入或长流程改成交付给用户的逐项人工用例。若 instrumentation 或测试框架在收尾时移除 / 替换目标包，所有 smoke 结束后必须再次执行保留数据覆盖安装，并核对包身份、版本和启动入口；最终交付设备状态以这次安装为准。
6. 文档和 Skill 底座至少执行：`node scripts/check-project-docs.mjs`、`node scripts/check-skills.mjs`、`git diff --check`。
7. 自动验证通过后，把剩余完整场景压缩为具体动作交给用户主测。
8. 用户反馈有问题时继续迭代；用户反馈无问题并明确要求提交后，才暂存和提交授权范围。推送仍需明确指令。

## 3. 强制边界

1. 默认只安装已校验的 debug APK 且使用保留数据覆盖安装；不卸载、清除数据、降级、安装 release 或重启设备。
2. 不默认创建提交、推送、GitHub Release、上传 APK 或公开发布。
3. 不回退或暂存用户未授权改动。
4. 不以“请整体手测”代替可执行验证。
5. 设备离线、构建失败、包身份 / 签名核对失败或最终覆盖安装失败时明确阻断，不把失败版本交给用户主测；不满足快速 smoke 条件时，不以未执行 smoke 作为代码失败，但必须保留“待用户主测”标记。
6. 物理设备必须使用显式独立 serial；禁止复用日常设备配置或隐式枚举全部在线设备。

## 4. 交付

说明改动摘要、本机与设备验证结果、安装版本、Git 状态、提交 / 推送 / 发布状态、客观阻断和用户主测清单。
