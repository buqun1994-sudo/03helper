## 2. V1 交付目标

1. 用户只下载并打开“03应用安装助手”，不必预先下载、解压、整理或选择 APK 文件。
2. 首次使用只让用户完成两件事：连接一台车机，以及选择是否附带 03 歌词和文件管理器；03桌面始终锁定为唯一必装核心。
3. 用户在组件选择页点击“开始安装”即完成第二步确认，之后下载、校验、发送、安装、授权和验证全部自动推进。
4. 首次成功后进入维护态，用户可以查看设备状态、检查更新、保留数据重新安装、修复授权、管理受控组件和清理安装缓存。
5. V1 不做任意 shell、车辆控制、账号体系、支付、车辆数据读取、后台常驻扫描或通用文件浏览器。

## 3. 视觉基线

### 3.1 设计来源与取舍

1. 视觉来源固定为 Cloud 新官网 `apps/website-next/` 当前 03歌词、03桌面独立产品页：复用平面分区、细边界、克制留白、Lucide 线性图标和中小圆角按钮，不参考已封存旧站。
2. 首次安装态必须使用整屏浅蓝背景，所有标题、说明、步骤、状态图标和进度内容以白色为主。内容区只允许使用低透明度白色蒙层和细白色边界，不能退回浅灰页面或大面积白底工作区。
3. 首次成功后的维护态保留同一蓝色背景，不切换为白色工具列表；维护入口改为大号、极简、按用途分组的按钮面，而不是小型列表行或卡片堆叠。
4. 安装助手是手机上的任务工具，不是官网：首屏不放车型图、`48px` 产品标题、产品轮播、营销 CTA、赞助区、页脚蓝雾、主题切换或装饰性背景。
5. 首版只提供这一套蓝色任务主题，不做独立深色主题。浅蓝表达通用、安全、健康；成功、提醒和错误继续使用小范围语义色，不能把所有状态压成单一蓝色。
6. 所有 UI 文本使用任务、状态、结果和下一步；不让普通车主阅读 ADB、端口、包名、命令、下载源名称、ZIP 或解压术语。

### 3.2 颜色与尺寸令牌

| 语义 | 值 | 用途 |
|---|---|---|
| 页面蓝底 | `#1976C5` | 首次安装与维护态的整屏背景；不使用渐变 |
| 深蓝按下态 | `#105C9D` | 白色主按钮文字、按压后的背景、少量强调 |
| 主白 | `#FFFFFF` | 标题、正文、线性图标、步骤、进度文字和主要内容 |
| 半透明白面 | `rgba(255, 255, 255, 0.14)` | 初始态信息块、维护大号分类按钮的静止表面 |
| 半透明白边界 | `rgba(255, 255, 255, 0.30)` | 分区、列表、按钮边界和进度底槽 |
| 辅助白文字 | `#F7FCFF` | 次要说明、版本、未开始步骤和辅助信息；层级用字号 / 字重区分，不降低到灰蓝低对比文字 |
| 白色主行动面 | `#FFFFFF` | 当前页面唯一主行动按钮；按钮文字使用 `#105C9D` |
| 成功绿 | `#B8F0D4` | 完成图标与局部强调；状态文字仍使用白色 |
| 提醒橙 | `#FFE1A6` | 提醒图标与局部强调；说明文字仍使用白色 |
| 错误红 | `#FFD1D1` | 错误图标与局部强调；错误文字仍使用白色 |

1. 普通按钮、输入面和必要弹层圆角上限为 `8dp`，图标按钮使用固定正方形触达区；不使用药丸形主按钮或大圆角页面卡片。
2. 顶部栏高度 `56dp`，主要底部按钮高度 `48dp`，普通列表项最小高度 `56dp`，组件选择项最小高度 `72dp`。
3. 页面左右边距 `20dp`，一级分区上下间距 `24dp`，列表内间距使用 `12dp` 或 `16dp`；所有固定尺寸在 `320dp` 至 `430dp` 宽度内保持稳定。
4. 标题使用系统无衬线字体，页面标题 `22sp`、区块标题 `18sp`、正文 `15sp`、说明 `13sp`；字距保持 `0`，长文字自然换行，不能遮挡按钮或状态。
5. 优先使用 Lucide 的 Compose 对应线性图标；存在标准图标时不得手绘 SVG。图标按钮必须有无障碍文本，陌生图标在长按或无障碍描述中说明用途。
6. 内容区使用 `1dp` 半透明白分隔线组织整行项目；组件选择、进度阶段和维护动作都不得通过悬浮阴影或嵌套卡片制造层级。

### 3.3 动效与反馈

1. 所有用户可见状态变化必须使用 `FastOutSlowInEasing`（`cubic-bezier(0.4, 0, 0.2, 1)`），禁止以静态替换、瞬间切换或无过渡的方式改变页面、按钮、阶段和结果。
2. 页面进入使用 `220ms` 的淡入加 `12dp` 向上短移，退出使用 `180ms` 的淡出加 `8dp` 向上短移；切换时新旧页面不得重叠出两套可读文字。
3. 初始态的步骤、组件行、结果行和维护分类按钮进入使用 `180ms` 淡入加 `8dp` 向上短移；同组按钮按 `24ms` 间隔依次进入，退出反向执行，不允许突然出现或消失。
4. 所有可点击按钮按下时在 `90ms` 内缩放至 `0.98` 并加深表面，释放或取消后在 `160ms` 内回到原状态；禁用、选中、错误和完成状态的颜色 / 边界变化同样使用 `160ms` 缓动。
5. 下载、安装和验证中的进度必须来自会话状态。解析下载页时使用短循环的进行中指示，不显示虚构百分比；取得文件长度后，真实字节进度和解压 / 校验进度以 `180ms` 缓动追随实际目标值。阶段完成图标使用 `160ms` 淡入和轻微缩放。
6. 不使用弹跳、果冻、视差、装饰性无限动画或大面积缩放；动效只服务于进入、退出、点击、进度和结果确认。
7. 成功、失败和提醒均由图标、颜色、标题和一句下一步组成，不能只靠颜色区分。

## 4. 首次安装信息架构

```text
冷启动
  -> 连接设备
  -> 选择应用
  -> 自动安装进度
  -> 安装结果
  -> 维护首页
```

1. 顶部只显示当前任务名和必要的返回或关闭动作；首次安装不显示维护工具导航。
2. 步骤条固定显示“连接设备 / 选择应用 / 正在安装”，只反映会话位置，不要求用户逐项处理后台步骤。
3. 在“选择应用”页点击“开始安装”属于第二步的确认动作；此后除取消、重试或失败恢复外，不要求用户继续点击。
4. 03桌面固定显示“必装”，不呈现可取消的开关；03 歌词和文件管理器使用可见的复选框并显示版本、体积和兼容范围。

## 5. 页面与可见文案

### 5.1 连接设备

| 情况 | 主标题 | 说明 | 主要动作 |
|---|---|---|---|
| 搜索中 | `正在查找车机` | `请让手机和车机保持在同一网络。` | `停止查找` |
| 找到设备 | `选择要连接的车机` | `点击后将建立并保持车机连接。` | 点击设备行 |
| 连接中 | `正在连接车机` | `正在建立稳定的车机连接，请稍候。` | `取消连接` |
| 未找到 | `暂未找到车机` | `确认手机和车机已连接同一网络后，再试一次。` | `重新查找` |
| 连接失败 | `暂时无法连接车机` | `请检查车机连接状态后重试。` | `重新连接` |

1. 设备列表按已确认设备优先、发现时间其次排序；只展示用户能判断的名称、连接状态和最近确认时间，不显示 IP、端口或内部 serial。
2. 点击设备行后必须先进入“正在连接车机”；只有真实连接握手成功才自动进入“选择应用”页。连接期间允许取消，失败时保留可重试入口。

### 5.2 选择应用

1. 页面标题为 `选择要安装的应用`，说明为 `03桌面会作为核心安装；其他应用可按需选择。`；说明下方固定显示 `已连接到 <车机名称>` 和确认图标。
2. `03桌面` 按固定顺序列为唯一必装组件，右侧显示锁定图标与 `必装`；`03歌词` 和 `文件管理器` 显示可切换复选框。所有组件下方显示来自版本清单的版本和体积。
3. 文件管理器作为第三项，使用复选框和 `可选` 标签；选择后立即把它纳入本次安装摘要。
4. 底部固定主按钮为 `开始安装`。按钮上方只显示本次组件数量和预计下载体积，不显示蓝奏云、R2、GitHub 或 APK 文件路径。
5. 版本清单无法获取时显示 `暂时无法准备安装应用`，主要动作是 `重新获取`；用户不能进入安装进度页。

### 5.3 自动安装进度

1. 页面标题为 `正在安装`，副标题显示当前车机名称；顶部显示可确定的会话进度，而不是猜测的百分比。
2. 依次展示五个稳定阶段：`正在获取安装包`、`正在检查安装包`、`正在发送到车机`、`正在授权`、`正在检查是否可用`。
3. 每个阶段只展示当前组件名、完成数量和可见状态。已完成阶段保持完成图标，当前阶段显示受状态驱动的小型进度，未开始阶段保持弱化。
4. `正在获取安装包` 内部先进行隐藏 WebView 页面解析，再显示 ZIP 的真实字节进度；解析期间使用不带伪百分比的进行中状态，取得 `Content-Length` 后才显示可计算百分比。页面不打开外部浏览器、不显示蓝奏云页面、不显示最终地址。
5. `正在检查安装包` 内部依次完成 ZIP 摘要、唯一 APK 解压、APK 摘要 / 包身份 / 证书校验和 ZIP 删除；解压过程只显示统一的检查进度，不出现文件管理器界面。
6. 下载源切换必须静默完成；只有全部来源失败时才显示 `安装包暂时无法获取`，说明为 `请检查网络后重新尝试。`。
7. 允许用户点击 `取消本次安装`。取消后保留已通过校验的文件和可恢复检查点，但页面文案只能显示 `安装已暂停`，不得称为完成。

### 5.4 安装结果与恢复

| 结果 | 主标题 | 说明 | 主要动作 |
|---|---|---|---|
| 全部成功 | `安装完成` | `安装和授权已完成，请在车机开始使用。` | `进入维护` |
| 可恢复中断 | `安装已暂停` | `恢复连接后，可以从上次进度继续。` | `继续安装` |
| 下载失败 | `安装包暂时无法获取` | `请检查网络后重新尝试。` | `重新尝试` |
| 安装失败 | `安装未完成` | `已保留可继续的进度。` | `继续安装` |
| 自动授权失败 | `自动授权未完成` | `助手未能完成自动授权，请保持手机与车机连接后重试。` | `重新授权` |

1. 成功页列出每个组件的“已安装 / 已完成授权 / 可用”结果，不展示原始命令输出。
2. 失败页只展示当前失败阶段、受影响组件和下一步；技术详情只能从维护态的脱敏诊断入口查看。

## 6. 维护态信息架构

1. 首次成功后，冷启动默认进入维护首页。整页保持 `#1976C5` 蓝色背景，顶部以白色显示已确认车机和最近状态；连接丢失时显示 `车机未连接` 与 `重新连接`。
2. 维护首页按任务分三组，每个动作都是大号极简分类按钮，而非小型列表或白底工具表：

| 分组 | 大号分类按钮 | 行为边界 |
|---|---|---|
| 常用 | `检查更新`、`重新安装`、`修复授权` | 复用同一安装会话与来源策略，不默认清除数据 |
| 应用 | `管理已安装应用`、`安装文件管理器`、`启动03歌词`、`启动03桌面` | 只处理审核过的组件，不提供任意 APK 或 shell 输入 |
| 存储与诊断 | `一键清理`、`导出诊断` | 一键清理只删除安装缓存、临时 APK 和已过期会话，不删除车机应用或车机数据；诊断默认脱敏 |

3. 分类标题使用 `13sp` 辅助白文字；按钮在 `360dp` 及以上宽度采用两列网格，`320dp` 至 `359dp` 采用单列。每个按钮最小高度 `112dp`、内边距 `16dp`、图标 `28dp`、标题 `18sp`、说明 `13sp`，表面使用半透明白面和细白边界，不使用阴影、嵌套卡片或渐变。
4. 大号按钮的图标、标题和说明均以白色系呈现；唯一需要立即确认的主行动可使用白色实底与深蓝文字，避免在蓝底上丢失操作焦点。
5. 卸载、清除数据、降级和重启车机不进入维护首页主动作。后续实现时放入单独的“高级操作”页面，逐项说明影响并二次确认。
6. 所有维护动作先显示目标车机和影响范围；断线、版本不兼容或组件不在审核清单内时停止并给出明确恢复入口。

## 7. 功能施工顺序

### F0：Android 工程与视觉基础

1. 建立 Kotlin Android 工程，UI 使用 Jetpack Compose；在工程创建后记录真实 `applicationId`、模块路径、主题文件和包名来源。
2. 建立本文件第 3 节的蓝底白字、半透明白面、尺寸、文字、状态和动效令牌；先完成系统字体、Lucide 图标入口和统一的 `FastOutSlowInEasing` 动效封装。
3. 先实现可驱动的 `InstallUiState` 映射、首次安装壳、维护大号分类按钮和全部进入 / 退出 / 点击 / 进度动效，不让 Compose 页面持有 ADB、WebView 或下载协议。
4. F0 已按长期总纲的真实锚点落地；Debug 变体用 `DebugScenarioActivity` 提供搜索、发现、选择、进度、成功、暂停、失败和维护场景，生产 `MainActivity` 不借用该夹具推进业务状态。
5. F0 验证只能证明手机工程、状态投影、视觉壳和基础动效可运行，不得据此宣称设备发现、组件下载、车机安装、授权或维护动作已经实现。

### F1：首次安装会话与页面接线

施工目标：把 F0 的静态快照契约变成唯一可推进、可取消、可恢复的 `InstallationSession`，让生产 `MainActivity` 和 Debug 演示都通过同一会话状态驱动；本阶段不接真实网络、WebView、ADB 或车机。

物理锚点与边界：

1. 新增 `app/src/main/kotlin/com/tcrrry/helper/domain/session/InstallationSession.kt` 与同目录的 `InstallationSessionCommand.kt`；文件头、包名和编码从现有 `InstallationSessionSnapshot.kt` 直接复制，owner 固定为 `com.tcrrry.helper.domain.session`。
2. `InstallationSession` 唯一持有 `MutableStateFlow<InstallationSessionSnapshot>`，只接受结构化 command / adapter result；UI 不得直接写快照，适配器不得直接改 Compose 状态。
3. 修改 `app/src/main/kotlin/com/tcrrry/helper/MainActivity.kt`：创建一个会话实例，用生命周期感知方式收集快照，并将 `InstallUiIntent` 映射为会话 command；删除当前固定 `IDLE` 快照入口，但保留 `InstallApp` 和 `InstallUiStateMapper` 作为唯一呈现主链。
4. Debug 场景只提供确定性 fake port / 事件序列，改为驱动同一个 `InstallationSession`；禁止在 `DebugScenarioActivity` 内复制一套状态转换逻辑。

微观状态规则：

1. `IDLE -> DISCOVERING` 由连接页进入前台或用户开始查找触发；同一前台周期不重复启动扫描，发现列表必须去重，未确认的设备不能进入 `CONNECTING`。
2. 用户点击已确认设备后进入 `CONNECTING`，应用层执行第二次 ADB 身份握手；只有 `DeviceConnectionConfirmed` 事件到达后才进入 `CONNECTED`，并保持一个连接租约。
3. `CONNECTED -> SELECTION_CONFIRMED` 只接受 03桌面必装且已选组件元数据完整的选择；`03桌面` 永远不能被取消，03歌词和文件管理器可按需切换。
4. `SELECTION_CONFIRMED` 之后按 `RESOLVING_SOURCE`、`DOWNLOADING_ARCHIVE`、`VERIFYING_ARCHIVE`、`EXTRACTING_APK`、`VERIFYING_ARTIFACTS`、`INSTALLING`、`AUTHORIZING`、`VERIFYING_DEVICE` 顺序推进；任何前置结果缺失都停在 `FAILED`，不得猜测跳过。
5. 取消、断线和可恢复错误进入 `PAUSED` 并保存会话检查点；重复事件、旧会话事件和未知事件不得覆盖更新后的快照。
6. 只有安装、授权和可用性三类结构化结果同时成立时，才允许 `SUCCEEDED`；成功动作进入维护态的意图仍由同一会话接收。

执行与验证：

1. 新增 `InstallationSessionTest`，至少覆盖正常全路径、必装锁定、可选项切换、取消 / 恢复、断线、重复事件、旧事件、前置校验失败和成功证据不足。
2. 保留并扩展 `InstallUiStateMapperTest`，验证所有内部状态到五类页面、按钮可用性、进度边界和恢复入口的唯一映射。
3. 先用 fake port 完成 Debug `flow` 的真实状态推进和手机运行 smoke，再进入 F2 的下载 / WebView，或 F3 的 LAN / ADB；本阶段不新增业务权限，不安装车机组件。
4. F1 完成标准是：生产入口不再硬编码快照；所有页面动作都能经由会话产生可观察状态变化；Debug 与生产共用同一 reducer / session owner；编译、直接单测和手机运行 smoke 全部通过。

5. F1 已完成：`InstallationSession` 以会话代次、事件序号和结构化检查点隔离旧事件；发现去重、设备确认、必装锁定、元数据门禁、严格阶段顺序、暂停 / 断线恢复、失败闭环和安装 / 授权 / 可用性证据门禁均由同一 owner 执行。F1 fake 只替代尚未施工的外部端口，不替代生产状态机。

6. F1 人工验收由用户明确跳过；该决定只表示暂不执行 Debug / 页面主测，不表示真实下载、设备安装或 F1 之外的外部能力已经验证。后续真实能力验收统一在对应下载、设备和安装链路完成后执行。

### F2：下载与发布清单

施工目标：把 F1 已有的 `RESOLVING_SOURCE`、`DOWNLOADING_ARCHIVE`、`VERIFYING_ARCHIVE`、`EXTRACTING_APK` 和 `VERIFYING_ARTIFACTS` 接上真实的受控下载与发布物完整性链路；本阶段不接 LAN、ADB、车机安装、授权或可用性验证。

物理边界与入口：

1. 先冻结 `ArtifactManifest`、`ResolvedDownloadRequest`、来源切换结果和结构化错误的最小 schema；清单只能声明签名发布物、哈希、包身份、版本和兼容范围，不能携带任意 shell、动态权限或运行时任意 URL。
2. 按长期总纲的 owner 建立 `ReleaseSourcePolicy`、`CloudReleaseCatalogAdapter`、`LanzouWebSourceAdapter`、`ArtifactDownloader`、`ArchiveIdentityVerifier`、`ArtifactArchiveExtractor` 和 `ArtifactIdentityVerifier`；它们通过端口把结构化结果送入 `InstallationSession`，不直接操作 Compose 状态。
3. 来源固定为“蓝奏云单组件 ZIP 分享页 -> Cloudflare R2 同字节 ZIP -> GitHub Releases 同字节 ZIP”；密码文件夹、三应用合并 ZIP、夸克和第三方直链转换器不进入自动会话。
4. 隐藏 WebView 使用 Android 默认手机端标识，挂载在当前安装页面背后并由不透明进度层遮挡；不启动外部浏览器、不接收用户触摸 / 焦点、不暴露 JavaScript bridge。取得下载回调或失败后立即停止加载并销毁。
5. 下载器只写入应用私有缓存的 `.zip.part`；ZIP 大小与 SHA-256 通过后才允许受控解压。唯一 APK 的 entry 名称、大小、SHA-256、包名、版本和签名证书全部通过后，才向会话发送产物校验成功，并立即删除 ZIP。
6. F2 实际文件边界固定为 `domain/artifact/`（清单、类型和策略）、`data/catalog/`（Cloud 验签与解析）、`data/web/`（隐藏 WebView）、`data/download/`（私有缓存与下载）、`data/artifact/`（ZIP / APK 校验）和 `application/artifact/`（事件编排）；事件只经 `InstallationSessionArtifactEventPort` 进入 F1 会话。
7. `ArtifactsVerified` 只记录完整性成功并停在 `VERIFYING_ARTIFACTS`；F2 不发送 `InstallationStarted`、安装、授权或车机可用性事件。

F2 验证门槛：

1. 先用确定性 fixture 覆盖清单签名 / 字段缺失、来源切换、HTML 假响应、解析超时、断点 / 重试、ZIP 哈希不符、ZIP 结构异常、路径穿越、多个 APK、APK 哈希 / 包身份 / 证书不符和缓存清理；任何失败都必须 fail closed，并把结构化原因送入现有会话。
2. 在真实 Android System WebView 和真实单组件 ZIP 证据具备前，不把模拟 User-Agent、桌面浏览器或 Debug fixture 记录为真实主源通过。
3. F2 完成后，F1 的页面仍只消费 `InstallUiStateMapper`；下载与校验进度、失败原因和备用源切换不得通过页面内特判表达。
4. 本轮按用户确认的最简自动化口径，只执行上述确定性 fixture、编译和直接相关单测；真实 WebView、真实 ZIP、网络切换和页面可见性由用户按 `docs/testing/验证矩阵.md` 的 F2 人工用例主测，不将未执行 smoke 计作失败或通过。

当前施工起点：先读取 `docs/architecture/项目长期总纲.md` 第 2、5、7 节、`docs/plans/03helper首版安装流程计划.md` 的 ZIP 自动处理契约、`docs/architecture/Cloud项目能力接线.md` 和 `docs/testing/验证矩阵.md`，再给出文件级物理锚点；未冻结清单 schema 前禁止自由创建外部协议。

## 8. V1 验收门槛

1. `360 x 800`、`390 x 844`、`412 x 915` 三个手机宽度下，标题、组件名、版本、进度和底部按钮均无截断、重叠或横向溢出。
