# 03helper 首版安装流程计划

## 1. 文档状态

1. 本文是“03应用安装助手”首版的方案和施工顺序；F0 Android 工程与 UI、F1 唯一安装会话、F2 下载 / 校验链以及 F3 局域网连接、真实 Debug 组件安装 / 授权 / 可用性编排已经落地。正式 Cloud 发布对象仍未具备，真实网络与车机完整闭环尚未完成。
2. 当前阶段完成工程与视觉基座后继续逐层接入应用流程；未取得对应验证证据前，不得把计划、接口草图或单一设备实测写成可发布能力。
3. 每个阶段完成后都要回写 `docs/progress.md`，并保留失败原因、验证证据和未完成门槛。

## 2. 已选主链

1. 用户只下载并安装“03应用安装助手”本体。
2. 助手启动后从固定控制端获取经过签名的版本清单，再按用户选择下载必装 03桌面与可选 03 歌词、文件管理器及其他组件的单组件 ZIP；本项目自有服务器只承载小体积清单，不承担安装包 600GB/月的直链主流量。
3. 蓝奏云无密码单组件 ZIP 分享页是国内自动主源，Cloudflare R2 是第一自动备用源，GitHub Releases 是第二自动备用源；三个自动来源发布同一 ZIP 字节，密码聚合文件夹、三应用合并 ZIP 与夸克只作人工或离线交付。
4. 客户端在手机本地完成 HTTPS、清单签名、ZIP 大小和 SHA-256、唯一 APK 解压、APK 大小和 SHA-256、包名、版本和 APK 签名证书摘要校验后，才允许向车机做非流式推送和安装。
5. 首次连接优先使用局域网发现并连接目标设备；OTG 只保留为待实证的实验入口，暂不进入正式 V1 主链。

### 方案取舍

| 方案 | 好处 | 主要代价 | 结论 |
|---|---|---|---|
| 方案 1：用户预先下载全部 APK，再只安装助手 | 首次安装可在无网环境继续；实现早期下载逻辑较少 | 用户要识别、保存和更新多份文件；版本容易过期；无法统一展示签名 / 兼容信息；客服和失败恢复路径分散 | 不作为默认主链，可在后续评估受控离线包 |
| 方案 2：只分发助手，运行后从固定来源下载组件 ZIP | 首次入口简单；清单、版本、签名和回滚可集中治理；蓝奏云、R2 和 Releases 承担对象流量，避免占用自有服务器 600GB/月直链额度；绕开蓝奏云手机端直下 APK 限制 | 首次安装依赖网络；蓝奏云需要应用内 WebView 执行手机页面；任一源不可达时必须有自动备用和清晰失败态 | 选定为默认主链；蓝奏云单组件 ZIP 是国内自动主源，R2 / Releases 依次自动兜底 |

蓝奏云 ZIP 分享页可以进入签名清单，但必须由安装助手自己的隐藏 Android System WebView 在安装进度页背后访问官方手机页面并截获最终 ZIP URL，不调用第三方直链转换服务，也不打开外部浏览器。截获后由应用自有原生下载器下载 ZIP、校验、解压并删除 ZIP；解析超时、返回 HTML、ZIP 校验失败或 APK 校验失败时自动切换 R2，再失败才切换 GitHub Releases。夸克仍只保留为人工 / 离线兜底。

### 蓝奏云调研结论（2026-08-18）

1. 用户看到的蓝奏云分享地址是下载页面地址；“转直链”是让页面完成自身正常流程后给出当次最终文件地址。命令行直接仿造中间请求会遇到动态 token、Cookie 和 HTML 验证页，因此安装助手不手工逆向隐藏字段，也不依赖第三方解析服务。
2. 免费蓝奏云在安卓手机端直接下载 APK 会被限制；用户已在真实安卓手机上扫码进入 ZIP 分享页，完成下载和解压，整个手工流程顺利。这是选择 ZIP 主链的直接产品证据。
3. 施工时不使用桌面浏览器或桌面 User-Agent 模拟手机下载。安装助手内嵌 Android System WebView，使用默认手机端标识，完成正常页面导航并接收 ZIP 下载回调；用户始终停留在安装助手的进度页。
4. WebView 只负责取得 ZIP 下载上下文，并把最终 URL、默认手机 User-Agent、当次 Cookie、Referer、Content-Disposition、MIME 和可得内容长度归一为内存态 `ResolvedDownloadRequest`。最终 ZIP 交给应用自有下载器写入私有缓存，再依次执行 ZIP 摘要校验、唯一 APK 解压、APK 身份校验和 ZIP 删除；不调用外部浏览器、系统下载页或用户的文件管理器，也不持久化短时 URL 或 Cookie。
5. F3 不再使用 A/B/C 临时空包。Debug 变体只读取 `app/src/debug/assets/real-debug/` 下的本地签名验证 profile，将 03桌面、可选 03歌词和文件管理器的真实 Debug ZIP 映射到真实包身份，并执行与产品主链相同的下载、ZIP / APK 校验和已选组件批量安装；全部安装完成后只执行一次固定综合授权命令，最后启动 03 桌面验证进程 / 必要服务，其他已选组件只核验安装存在性。Release 变体不读取该 profile，正式 Cloud 资料缺失时继续 fail closed。
6. F3 输入 ZIP 必须在根目录只包含一个 APK，不接受 `__MACOSX`、子目录或第二个 entry。链接、ZIP / APK 大小与摘要、包名、版本和证书必须逐项验真后才写入 Debug profile；候选更新时必须重新签发 profile，不能沿用旧摘要。
7. 结论：蓝奏云单组件 ZIP 进入国内自动主链；R2 / GitHub Releases 保持自动备用，解决页面改版、限流或单点不可用。当前先用真实 Debug 组件证明完整工程链，结果只作为 F3 验证证据，不等于生产发布身份或 Cloud 正式候选通过。

### ZIP 自动处理契约

1. 发布方每个组件只生成一次 ZIP，并将同一字节文件上传到蓝奏云、R2 和 GitHub Releases。ZIP 根目录必须只有一个普通 APK 文件；其文件名、ZIP 大小和 SHA-256、APK 大小和 SHA-256 都写入签名清单。
2. 助手先以 `.zip.part` 下载到应用私有缓存。ZIP 校验通过后才解压到 `.apk.part`；只有唯一 entry 名称精确匹配、输出大小精确匹配并通过 APK 身份校验，才将它转为可安装 APK。
3. 解压成功并完成 APK 校验后立即删除 ZIP。ZIP 或 APK 任一校验失败时删除 ZIP、部分 APK 和无效 APK，再按蓝奏云 → R2 → GitHub Releases 的固定顺序切换。
4. 已校验 APK 只为当前可恢复安装会话保留；安装、授权和可用性验证全部成功后删除。暂停或断线恢复时可以保留当前清单版本下的已校验 APK；“一键清理”删除所有缓存。

## 3. 里程碑

### M0：契约和发布身份

1. 固定组件清单 schema、签名公钥分发方式、来源切换规则、设备能力模型和错误分类。
2. 为 03歌词、03桌面和可选文件管理器确认可验证的包身份、兼容范围和发布签名；身份缺失时阻断后续自动发布。

### M1：首次安装壳与状态机

1. 建立首次安装和维护态的唯一状态机，用户动作只保留设备连接、组件选择和开始确认。
2. 为发现、下载、校验、安装、授权、验证、暂停、失败和恢复定义可观察状态与取消语义。
3. 当前状态：F1 已完成并通过本机低成本验证；用户明确跳过 F1 人工验收，不将该人工项目记录为通过。后续真实下载和设备链路仍必须在对应阶段完成运行级验证。

### M2：局域网设备通道

1. 以有界广播、去重、超时和显式设备选择完成局域网发现；发现探测只负责筛选候选，不冒充用户已建立的持续连接。
2. 用户选择候选后，用结构化 ADB 连接端口完成第二次真实握手并持有连接租约；租约贯穿初始化和维护态，只有用户主动断开、重新发起发现、进程结束或客观掉线时释放；无线调试自动开启不作为首次连接前的承诺。
3. 只有在手机和车机 USB 角色、权限及 ADB USB 行为都有设备证据后，才评审 OTG 是否进入后续版本。

### M3：清单、下载和完整性校验

1. 实现隐藏 Android WebView 的蓝奏云 ZIP 解析主源、应用自有原生 ZIP 下载器、`ArtifactArchiveExtractor`、R2 第一备用源、GitHub Releases 第二备用源和缓存生命周期；源切换只能由固定策略触发。
2. 覆盖清单过期、ZIP 哈希不符、ZIP 结构不符、缺少唯一 APK、路径穿越 entry、APK 哈希不符、证书不符、版本回退、体积超限、断网恢复和 ZIP 删除等确定性反例。
3. 真实运行级 smoke 必须证明：外部浏览器没有启动；用户只看到安装助手进度页；隐藏 WebView 获取下载回调；ZIP 下载、解压、APK 校验和 ZIP 删除按顺序完成。没有手机端运行证据时不得写成真实通过。
4. 当前状态：本地发布清单、来源策略、下载 / 校验端口和 `InstallationSession` 接线已完成；F3 以 Debug 本地签名 profile 继续验证真实蓝奏云与设备主链，正式 Cloud profile 仍保持独立发布门禁。

### M4：安装、授权和可用性验证

1. 对已校验 APK 执行非流式推送、安装和包身份核对。
2. 授权动作按版本化白名单执行：先读原值，幂等追加，回读确认；不得覆盖已有通知或无障碍授权。
3. 所有已选 APK 全部安装完成后才进入一次统一授权阶段；只有所有已选组件安装证据、统一授权回读证据、03 桌面启动 / 进程 / 必要 Service 证据和其他已选组件安装存在性证据齐全，才向用户报告成功。
4. 当前代码已接入批量安装后 APK 拉回核验、授权声明门禁、一次固定综合授权命令和仅 03 桌面启动 / 进程 / Service 证据；目标 Android 9 车机的真实结果仍以本轮设备闭环为准，不能用单测或现有已安装状态替代。

### M5：维护态

1. 首次成功后开放检查更新、保留数据重装、修复授权、重启服务、缓存清理、受控安装 / 卸载和脱敏诊断。
2. 清数据、卸载、降级、重启设备等破坏性动作单独分级、说明影响并二次确认。

### M6：发布门禁

1. 在真实设备和独立测试环境跑完验证矩阵中的必须通过项，并保存清单、哈希、签名、回滚和 smoke 证据。
2. 以下任一项未完成都不能宣称正式分发就绪：03桌面长期 Release 签名、03歌词 production 发布身份、文件管理器从 Debug 身份迁移并履行 GPL 义务。

## 4. 不变边界

1. 03桌面是首次安装唯一必装项且不可取消；03 歌词和文件管理器是显式可选项。
2. 远端清单只描述审查过的发布物和兼容元数据，不下发任意 shell、脚本或动态权限。
3. 安装助手只编排外部 APK，不复制 03 歌词、03桌面的业务逻辑，也不把 ADB 变成它们的运行依赖。
4. 所有未验证设备能力、下载协议和发布身份保持 `待验证 / 阻断` 状态，不能用 UI 文案暗示已经可用。

## 5. 交付标准

1. 代码交付前，文档路由、Skill 元数据和文本质量检查全部通过。
2. Android 代码交付前，必须补齐与本阶段直接相关的清单、状态机、完整性和设备动作测试；构建后使用显式测试手机保留数据覆盖安装并执行已有最小 smoke。真实车机写入只在包身份、非破坏性边界或当次破坏性授权明确满足时执行。
3. 发布交付前，必须由用户明确授权正式签名、生产源切换、发布和推送；本计划本身不授权这些动作。
