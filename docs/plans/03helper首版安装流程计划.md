# 03helper 首版安装流程计划

## 1. 文档状态

> 现行版本字段口径：启用应用必须携带 `versionCode`、`versionName`、`apkSizeBytes`。客户端选择页显示 `v1.2.3`、`2.6M`；下载后从 APK 读取包名与发布者证书做最小身份校验，版本、大小和摘要仅作为传输证据。

1. 本文是“03应用安装助手”首版的方案和施工顺序；F0 Android 工程与 UI、F1 唯一安装会话、F2 下载 / 校验链以及 F3 局域网连接、真实 Debug 组件安装 / 授权 / 可用性编排已经落地。正式 Cloud 发布对象仍未具备，真实网络与车机完整闭环尚未完成。
2. 当前阶段完成工程与视觉基座后继续逐层接入应用流程；未取得对应验证证据前，不得把计划、接口草图或单一设备实测写成可发布能力。
3. 每个阶段完成后都要回写 `docs/progress.md`，并保留失败原因、验证证据和未完成门槛。

## 2. 已选主链

1. 用户只下载并安装“03应用安装助手”本体。
2. 助手启动后从固定控制端获取 Cloud schema V4 签名分发配置（兼容读取没有 Logo 的 v3 历史快照），配置包含一个蓝奏密码根文件夹、动态 `apps[]` 快照和受摘要固定的兼容性 Logo 元数据；每个条目提供文件名、展示信息、`versionCode`、`versionName`、`apkSizeBytes`、启用状态、安装策略、排序、客户端能力门槛和受限 typed `deviceSetup`。选择页直接显示 `v1.2.3`、`2.6M` 等规范化字段，`catalogVersion` 只作内部修订。初始化 Logo 固定使用应用内置的最新资源；客户端按用户选择先检查公共 `Download` 中匹配 APK，验签后从 APK 读取并缓存图标，只有未命中 APK 的组件才获取 ZIP。包名、证书、最低 SDK 和 APK 实际身份由客户端本地读取 / 官方发布者证书根校验，网络 payload 不得覆盖；版本、大小和摘要仅作为传输证据。本项目自有服务器只承载小体积配置，不承担安装包 600GB/月的直链主流量。
3. 蓝奏密码根文件夹是远端定位主源；客户端每次重新枚举根目录，未声明文件忽略，声明 ZIP 缺失只记录对应 APP。用户确认后先检查手机公共 `Download` 中与包名 / 受信证书匹配的 APK，未命中时才下载 ZIP，读取 APK 的包名、发布者证书以及传输证据。密码、Cookie、Referer 和短时直链只在本次流程内存中使用。
4. 客户端在手机本地完成 HTTPS、清单签名、ZIP 大小和 SHA-256、唯一 APK 解压和包名 / 发布者证书最小身份校验后，才允许向车机做非流式推送和安装；APK 大小、版本与摘要不再与 Cloud 展示字段重复做准入比对。
5. 首次连接优先使用局域网发现并连接目标设备；OTG 只保留为待实证的实验入口，暂不进入正式 V1 主链。

### 方案取舍

| 方案 | 好处 | 主要代价 | 结论 |
|---|---|---|---|
| 方案 1：用户预先下载全部 APK，再只安装助手 | 首次安装可在无网环境继续；实现早期下载逻辑较少 | 用户要识别、保存和更新多份文件；版本容易过期；无法统一展示签名 / 兼容信息；客服和失败恢复路径分散 | 不作为默认主链，可在后续评估受控离线包 |
| 方案 2：只分发助手，运行后从签名配置指定的蓝奏根文件夹获取组件 | 首次入口简单；后台只维护一个根文件夹；Cloud 字段直接驱动展示；公共 `Download` 可复用用户已有 APK；绕开蓝奏云手机端直下 APK 限制 | 首次安装仍可能依赖网络；密码根文件夹需要应用内 WebView 验证；远端单个包不可用时结果页需解释 | 选定为默认主链；Cloud `apps[]` 是展示控制面，公共 `Download` 与受控远端 ZIP 是按 APP 选择的来源 |

蓝奏密码根文件夹的地址和密码进入 V3 签名配置，但不进入用户可见界面。连接车机后，安装助手先验签配置并用自己的隐藏 Android System WebView 完成密码验证和文件枚举，只把 Cloud 应用行交给选择页，不下载 ZIP、不解析 APK。用户点击“开始下载并安装”后，每个已选 APP 先扫描公共 `Download` 中的匹配 APK；未命中时才取得当次下载上下文，由应用自有原生下载器以最多 2 个并发任务下载、校验、解压并读取 APK 身份，再发布到公共 `Download`。进度页统一投影获取、检查、发送、授权、检查可用性五个阶段和真实百分比，底部不提供取消安装按钮，只提示保持亮屏并等待完成。单个 APP 缺失或校验失败只更新该 APP 状态，结果页统一展示失败原因；只有 `desktop` 有完整可用证据时才提供进入维护动作。

### 蓝奏云调研结论（2026-08-18）

1. 用户看到的蓝奏云分享地址是下载页面地址；“转直链”是让页面完成自身正常流程后给出当次最终文件地址。命令行直接仿造中间请求会遇到动态 token、Cookie 和 HTML 验证页，因此安装助手不手工逆向隐藏字段，也不依赖第三方解析服务。
2. 免费蓝奏云在安卓手机端直接下载 APK 会被限制；用户已在真实安卓手机上扫码进入 ZIP 分享页，完成下载和解压，整个手工流程顺利。这是选择 ZIP 主链的直接产品证据。
3. 施工时不使用桌面浏览器或桌面 User-Agent 模拟手机下载。安装助手内嵌 Android System WebView，使用默认手机端标识，完成正常页面导航并接收 ZIP 下载回调；用户始终停留在安装助手的进度页。
4. WebView 只负责取得 ZIP 下载上下文，并把最终 URL、默认手机 User-Agent、当次 Cookie、Referer、Content-Disposition、MIME 和可得内容长度归一为内存态 `ResolvedDownloadRequest`。最终 ZIP 交给应用自有下载器写入私有缓存，再依次执行 ZIP 摘要校验、唯一 APK 解压、APK 身份校验和 ZIP 删除；不调用外部浏览器、系统下载页或用户的文件管理器，也不持久化短时 URL 或 Cookie。
5. F3 不再使用 A/B/C 临时空包。Debug 变体只读取 `app/src/debug/assets/real-debug/` 下的内置 V3 staging 公钥，并按签名 `apps[]` 与源码官方发布者证书根处理 03桌面、可选 03歌词和后续 APP ZIP；随后执行与产品主链相同的下载、ZIP / APK 校验和已选组件批量安装。全部安装完成后只执行一次按 `apps[]` 动态生成的版本化授权计划，最后启动 03 桌面验证进程 / 必要服务，其他已选组件只核验安装存在性。Release 变体不读取 Debug 公钥，正式 Cloud 资料缺失时继续 fail closed。
6. F3 输入 ZIP 必须在根目录只包含一个 APK，不接受 `__MACOSX`、子目录或第二个 entry。链接、ZIP / APK 大小与摘要作为传输证据记录，包名与发布者证书作为身份准入真值；候选更新时必须重新核对发布者身份，不能沿用旧证书资料。
7. 结论：蓝奏密码根文件夹进入当前自动主链，Cloud `apps[]` 的版本 / 大小字段是选择页展示真值，公共 `Download` 与远端 ZIP 共同构成本次 APP 的受控来源；当前先用真实 Debug 组件证明完整工程链，结果只作为 F3 验证证据，不等于生产发布身份或 Cloud 正式候选通过。

### ZIP 自动处理契约

1. 发布方按 `apps[]` 生成任意数量的单 APP ZIP，把本批 ZIP 上传到同一个不可变密码根文件夹，完成目录 / ZIP / APK 预检后再发布签名配置；目录可暂时缺少任一声明 ZIP，客户端会先尝试公共 `Download`，不要求目录只包含声明文件。
2. 连接阶段只读取配置和根目录；用户确认后，助手先检查手机公共 `Download` 目录中是否已有通过目标包名与受信证书校验的 APK，命中则直接复用并记录大小 / SHA-256；未命中时按最多 2 个并发任务下载 ZIP 到应用私有缓存，校验归档结构后解压唯一 APK，校验通过后把 APK 发布到公共 `Download`。
3. 每次检查更新都重新执行配置读取和目录枚举；Cloud `versionName`、`versionCode` 或 `apkSizeBytes` 变化即更新选择页展示，实际 APK 身份只按包名与发布者证书准入，其余字段作为传输 / 更新证据。未声明文件忽略，任一 APP 的目录缺失或单项失败不阻断其它 APP；`desktop` 不可用时只影响最终是否能进入维护，不把安装页冻结为暂停。
4. 已校验 APK 保留在公共 `Download` 供用户维护和下次复用；临时 ZIP / 分片才按会话生命周期清理，“一键清理”只删除助手生成的 `03helper-` APK 和私有临时文件，不删除用户其它安装包。

## 3. 里程碑

### M0：契约和发布身份

1. 冻结动态 `apps[]` schema、签名公钥分发方式、修订防回滚、来源切换规则、设备能力模型和错误分类。
2. 为 desktop 及后续 APP 确认官方发布者证书根和包命名空间；包身份由客户端从 APK 读取，Cloud 不得覆盖。新证书必须先完成客户端信任根更新。

### M1：首次安装壳与状态机

1. 建立首次安装和维护态的唯一状态机，用户动作只保留设备连接、组件选择和开始确认。
2. 为发现、下载、校验、安装、授权、验证、暂停、失败和恢复定义可观察状态与取消语义。
3. 当前状态：F1 已完成并通过本机低成本验证；用户明确跳过 F1 人工验收，不将该人工项目记录为通过。后续真实下载和设备链路仍必须在对应阶段完成运行级验证。

### M2：局域网设备通道

1. 以有界广播、去重、超时和显式设备选择完成局域网发现；发现探测只负责筛选候选，不冒充用户已建立的持续连接。
2. 用户选择候选后，用结构化 ADB 连接端口完成第二次真实握手并持有连接租约；租约贯穿初始化和维护态，只有用户主动断开、重新发起发现、进程结束或客观掉线时释放；无线调试自动开启不作为首次连接前的承诺。
3. 只有在手机和车机 USB 角色、权限及 ADB USB 行为都有设备证据后，才评审 OTG 是否进入后续版本。

### M3：清单、下载和完整性校验

1. 实现签名配置读取、隐藏 Android WebView 的密码根文件夹解析、应用自有原生 ZIP 下载器、`ArtifactArchiveExtractor` 和缓存生命周期；签名 `catalogRevision` 与 `apps[]` 字段决定本次控制面快照和选择页展示，ZIP / APK 只负责各 APP 的来源定位与安装前完整性校验，不能由任意运行时 URL 或 ZIP 行元数据改写版本展示。
2. 覆盖清单过期、配置修订回退、ZIP 哈希不符、ZIP 结构不符、缺少唯一 APK、路径穿越 entry、APK 证书不符、体积超限、断网恢复和 ZIP 删除等确定性反例。
3. 真实运行级 smoke 必须证明：外部浏览器没有启动；用户只看到安装助手进度页；隐藏 WebView 获取下载回调；ZIP 下载、解压、APK 校验和 ZIP 删除按顺序完成。没有手机端运行证据时不得写成真实通过。
4. 当前状态：本地签名配置、根文件夹来源策略、动态下载 / 校验端口和 `InstallationSession` 接线已完成；F3 以 Debug 配置继续验证真实蓝奏云与设备主链，正式 Cloud distribution-config 仍保持独立发布门禁。

### M4：安装、授权和可用性验证

1. 对已校验 APK 执行非流式推送、安装和包身份核对。
2. 授权动作按版本化白名单执行：先读原值，幂等追加，回读确认；不得覆盖已有通知或无障碍授权。
3. 每个已选 APK 独立安装并记录结果；单个安装 / 授权 / 可用性失败时跳过该 APP 继续处理其它 APP。只有所有已选组件都通过时报告成功，否则进入部分失败结果页；03 桌面成功时仍允许进入维护。
4. 当前代码已接入批量安装后 APK 拉回核验、授权声明门禁、按 typed `deviceSetup` 生成的动态授权计划和仅 03 桌面启动 / 进程 / Service 证据；目标 Android 9 车机的真实结果仍以本轮设备闭环为准，不能用单测或现有已安装状态替代。

### M5：维护态

1. 首次成功后开放检查更新、保留数据重装、修复授权、重启服务、缓存清理、受控安装 / 卸载和脱敏诊断。
2. 清数据、卸载、降级、重启设备等破坏性动作单独分级、说明影响并二次确认。

### M6：发布门禁

1. 在真实设备和独立测试环境跑完验证矩阵中的必须通过项，并保存清单、哈希、签名、回滚和 smoke 证据。
2. 以下任一项未完成都不能宣称正式分发就绪：03桌面长期 Release 签名、03歌词 production 发布身份、文件管理器从 Debug 身份迁移并履行 GPL 义务。

## 4. 不变边界

1. `desktop` 是首次安装唯一核心必装项且不可取消；其余启用 APP 按 `apps[]` 动态呈现为显式可选或建议安装项。
2. 远端清单只描述审查过的目录、展示信息、安装策略和 typed `deviceSetup`；不下发或覆盖 `packageName`、`certificateSha256`、`minAndroidSdk`，不下发任意 shell、脚本或动态设置名。
3. 安装助手只编排外部 APK，不复制 03 歌词、03桌面的业务逻辑，也不把 ADB 变成它们的运行依赖。
4. 所有未验证设备能力、下载协议和发布身份保持 `待验证 / 阻断` 状态，不能用 UI 文案暗示已经可用。

## 5. 交付标准

1. 代码交付前，文档路由、Skill 元数据和文本质量检查全部通过。
2. Android 代码交付前，必须补齐与本阶段直接相关的清单、状态机、完整性和设备动作测试；构建后使用显式测试手机保留数据覆盖安装并执行已有最小 smoke。真实车机写入只在包身份、非破坏性边界或当次破坏性授权明确满足时执行。
3. 发布交付前，必须由用户明确授权正式签名、生产源切换、发布和推送；本计划本身不授权这些动作。
