# 03helper 验证矩阵

## 0. 当前验证口径

1. “最简自动化 + 用户人工主测”不等于跳过可测试产物：Android 工程变更必须先完成语法 / 编译、直接相关确定性单测、Debug APK 构建，并在显式测试设备可用时执行保留数据覆盖安装。
2. 覆盖安装后只执行已有、稳定、预计单条不超过 5 分钟且无破坏性动作或未具备外部前置的最小 smoke；复杂真实 WebView、真实 ZIP、切网、Range 续传、车机写入和长流程交给人工主测。若 smoke 框架会移除或替换目标包，必须在全部 smoke 结束后再次保留数据覆盖安装并核对包身份与启动入口，最终设备状态以最后一次安装为准。每条人工用例必须按设备前提、动作、预期结果和停止条件执行。任何 fixture 或模拟下载结果都不计为真实源通过。
3. 当前 Debug 主链验证签名配置、蓝奏密码根文件夹动态枚举、三个 ZIP 下载 / 解压 / APK 身份读取，并按用户选择执行批量安装、一次统一授权和可用性完整主链。根文件夹是唯一自动版本真值；R2 / GitHub 不参与当前版本判断，Debug 结果不等于生产发布通过。
4. 设备离线、安装失败或不满足快速 smoke 门槛时，明确记录阻断或“待用户主测”；不因未执行复杂 smoke 阻断代码交付，但不得把它写成真实通过。

## 1. 低成本闭环

### 1.0 F3 直接自动化覆盖

1. `Ipv4Subnet` 必须排除网络地址和广播地址；`LanAdbDeviceDiscovery` 必须对重复候选和重复设备身份去重，并在有界并发、超时和取消后返回结构化结果。
2. `DeviceDiscoverySessionAdapter` 必须按同一事件端口发送设备确认和发现结束事件；点击设备后 `InstallationSession` 必须先进入 `CONNECTING`，只有持久在线连接适配器发出 `DeviceConnectionConfirmed` 才能进入 `CONNECTED`。
3. `InstallerRuntime` 必须在 `CONNECTED`、初始化阶段、成功结果和维护态持有同一连接租约；清单加载失败不得释放租约，只有维护页主动断开、重新发起发现、进程结束或健康检查确认掉线时释放。
4. Release 生产工厂在 Cloud Android profile、公钥或组件映射缺失时必须返回 `catalog_android_profile_missing`；Debug 工厂只接受编译进 Debug 变体且验签通过的真实组件 profile。两者不能互相读取信任资料。
5. `MainActivity` 首次创建和重新进入前台时必须通过 `InstallerRuntime.onForeground()` 自动启动一次发现；同一前台周期不得重复扫描，用户主动停止后不得立即自启。
6. 已核验 APK 必须与同一条连接租约交给 `DeviceInstallationCoordinator`；安装后必须拉回车机实际 APK 并核对大小、SHA-256、包名、版本和证书，再进入授权阶段。
7. 授权声明校验必须发生在所有已选组件批量安装证据完成后、任何 app-op 或 secure settings 写入前；声明缺失时保留安装证据、授权写入次数为零。成功态必须同时具备所有已选组件安装证据、一次统一授权回读证据、03 桌面启动 / 进程 / 必要 Service 证据以及其他已选组件安装存在性证据。
8. `MaintenanceController` 必须通过同一 `InstallationSession` 发布维护动作的 `RUNNING`、`SUCCEEDED` 或 `FAILED` 结果；同一时刻最多一个动作，车机动作无租约时必须结构化失败，检查更新、清理和诊断不得依赖车机连接。
9. `MaintenanceSessionStore` 必须拒绝损坏 JSON、未知 schema、非法来源 / 包身份 / 组件集合和超大记录；有效记录冷启动后只能恢复为 `MAINTENANCE + DISCONNECTED`，不能恢复活动动作或短时下载上下文。
10. 维护重连必须保留原清单、组件选择和安装 / 配置 / 可用证据；停止发现、无设备、设备不一致和握手失败回到维护断线态，同一设备确认后恢复维护态且不重新加载首次安装清单。
11. `InstallUiStateMapper` 与 `MaintenanceHome` 必须从快照投影维护反馈、断线动作禁用和三受控组件安装状态，不在页面维护第二套状态机。

| 变更类型 | 必须执行 | 覆盖结果 |
|---|---|---|
| 文档、规则、Skill、脚本 | `node scripts/check-project-docs.mjs`、`node scripts/check-skills.mjs`、`git diff --check` | 路由、底座结构、Skill 元数据和文本质量 |
| 领域 / 应用逻辑 | 语法或类型检查、直接相关单测 | 状态机、错误语义、取消与恢复 |
| 下载 / 清单 / 解压 | 确定性 fixture、ZIP / APK 双摘要反例、归档结构反例、网络失败测试 | 供应链完整性、受控解压、缓存清理与备用源边界 |
| ADB / 设备连接 | 假设备契约、定向 serial 快检、断线与超时 | 连接、取消、重连和设备隔离 |
| UI、启动、导航、输入 | 真实运行级 smoke、关键状态截图或可观察日志 | 用户主路径和错误态 |
| 安装 / 授权 / 维护 | 保留数据覆盖安装、版本 / 签名核对、最小设备 smoke | 包身份、授权回读、进程和服务可用性 |

文档阶段还必须保持以下边界：计划中的测试不能被记录为已执行；没有真实设备、签名身份或发布源证据时，条目标记为“待验证 / 阻断”。

## 1.1 F2 人工主测用例

以下用例是交付给用户的最小完整主测集。每条用例都必须在真实 Android 手机上执行；任一“停止条件”出现时停止该条，不把后续阶段猜测为成功。满足快速 smoke 门槛的启动与入口检查由 AI 先完成，复杂真实链路仍由用户主测。

发布资料的准备责任属于项目 / Cloud 发布方，不属于用户的测试动作。用户不需要自行寻找、生成、签发或上传 Android profile、公钥或组件 ZIP。AI 可以对本地仓库和已授权的公开资料做只读核对，但不能替发布方签发受信清单，也不能把缺失的发布资料伪造成可测试候选；资料未具备时只记录客观阻断。

1. **分发配置信任与根目录边界（发布门禁）**
   - 前提：由项目 / Cloud 发布方提供一份已签名的 distribution-config、对应受信公钥、可访问的密码根文件夹和三个配置指定的 ZIP。若任一资料尚未发布，用户不需要补齐，直接记录“外部发布前置阻断”并停止本条。
   - 动作：在候选资料具备后启动安装；确认客户端先验签配置，再在隐藏 WebView 中打开根文件夹并按三个文件名枚举。替换一个 ZIP 后重新执行检查更新，观察客户端是否从 APK 内读取新的版本 / 大小 / SHA-256。
   - 预期：只有有效签名、未过期且字段完整的配置进入目录解析；根目录缺失、重复、未知文件或密码错误时整次拒绝，不显示任意网盘页面或部分更新。
   - 停止条件：签名错误仍进入下载、密码 / 短时 URL 被持久化、目录外文件被接受、或只更新部分组件仍被报告为成功。
2. **隐藏 WebView 回调**
   - 前提：安装助手 Debug / 候选包、Android System WebView 已更新，手机可访问签名配置指定的密码根文件夹。
   - 动作：从安装助手开始安装，观察整个根目录解析阶段；不点击页面、不切到浏览器；等待密码验证、文件枚举、下载回调、解析超时和页面失败各执行一次。
   - 预期：外部浏览器不启动，蓝奏云页面不出现在屏幕或最近任务，WebView 不接受触摸 / 焦点；成功回调后立即进入原生下载，失败或超时后 WebView 停止并销毁，用户只看到安装助手自己的进度。
   - 停止条件：出现外部浏览器、可见网页、需要用户点下载、或失败后 WebView 仍持续活动。
3. **私有 ZIP 下载、取消与恢复**
   - 前提：选择一个可观察长度的真实 ZIP，清单中的 ZIP 大小 / SHA-256 与对象一致。
   - 动作：下载中取消一次；在同一清单版本、同一来源类型下继续；再换成另一来源类型继续；检查应用私有缓存和用户可导出的诊断内容。
   - 预期：下载先写 `.zip.part`；取消保留可恢复部分和检查点；同一来源可发起 Range 续传，来源类型变化时从零开始；缓存 / 诊断不含短时 URL、Cookie 或 Referer。
   - 停止条件：把不同来源的字节拼接、取消后丢失或误用旧片段、或敏感上下文被持久化。
4. **目录整体一致性与更新识别**
   - 前提：根文件夹中恰好有三个配置指定 ZIP，且每个 ZIP 根目录只有一个对应 APK。
   - 动作：完成一次检查更新；人工替换其中一个 ZIP，再次执行检查更新；再分别加入未知文件、重复文件、缺失文件和错误密码。
   - 预期：任一 ZIP 的 APK 版本、大小或摘要变化都会形成新的整体候选；未知、重复、缺失或身份不符时整次目录拒绝，不留下部分候选。
   - 停止条件：固定旧版本仍被缓存命中、部分组件更新被报告为全部成功、或错误目录仍进入选择页。
5. **ZIP 校验与受控解压**
   - 前提：准备确定性 ZIP fixture：正确 ZIP、大小错误、SHA-256 错误、损坏 ZIP / CRC 错误、空 ZIP、`../`、绝对路径、嵌套目录、多个 APK、额外普通文件和输出超出清单上限。
   - 动作：逐个替换当前来源对象并开始安装。
   - 预期：大小和 SHA-256 通过前绝不解压；只有根目录中清单指定的唯一 APK 可解压；任何反例都清理 ZIP、`.zip.part`、`.apk.part` 和无效 APK，并按固定源策略切换或停止。
   - 停止条件：校验失败仍创建 APK、路径穿越写出缓存根目录、接受第二个文件、或清理不完整。
6. **APK 身份校验与 ZIP 生命周期**
   - 前提：准备 APK 摘要正确 / 错误、包名错误、版本名或 versionCode 错误、签名证书摘要错误的 fixture；清单记录真实身份。
   - 动作：逐个执行解压和身份校验，观察会话阶段和应用私有缓存。
   - 预期：大小、SHA-256、包名、版本和证书全部通过后才产生产物验证成功事件；成功立即删除 ZIP，保留当前会话可用的已校验 APK；任一失败清理 ZIP、部分 APK 和无效 APK。
   - 停止条件：任一身份字段不符仍进入安装、ZIP 未删除、或无效 APK 留在缓存。
7. **唯一会话与层级门禁**
   - 前提：从同一 `InstallationSession` 进入选择确认，并完成一组成功或失败 fixture。
   - 动作：先单独验证 F2 协调器只产出已核验 APK，再由生产运行时把该结果交给 F3 设备协调器。
   - 预期：来源、下载、ZIP、解压、APK、安装、授权和可用性证据都进入同一会话；F2 单层成功停在 `VERIFYING_ARTIFACTS`，生产运行时随后显式发送 `InstallationStarted`，不存在页面或 Activity 自行推进状态。
   - 停止条件：页面或 Debug 场景出现第二套状态、未收到设备协调器事件就进入安装，或日志文本替代结构化证据。

## 2. 首次安装主路径

1. 冷启动助手，确认首屏是整屏 `#1976C5` 浅蓝背景，标题、说明、步骤、状态和进度内容以白色为主；进入连接页后自动开始一次有界查找，不应先要求用户点击“重新查找”；首屏只显示首次安装入口和必要状态，助手本体不要求用户先整理其它 APK。
2. 让手机和当前样本车机处于同一局域网，确认有界发现、去重、显式设备选择和连接超时；记录 `S56_HQX`、Android 9、TCP `5555` 和 ADB 状态，不能把“端口可达”当作所有能力已打开。
3. 选择设备行后，确认页面先显示“正在连接车机”并等待真实连接结果；连接成功后进入选择页，并显示“已连接到 <车机名称>”。选择组件，确认 03桌面不可取消，03 歌词和文件管理器可切换，版本、预计下载体积和兼容范围可见；用户界面不显示下载源、ZIP 路径或 APK 路径。
4. 让 `LanzouWebSourceAdapter` 用 Android System WebView 的默认手机端标识读取清单中的固定 ZIP 分享页，确认外部浏览器没有启动、蓝奏云页面不可见且无需用户点击即可取得最终 ZIP URL；页面解析阶段只显示安装助手自己的准备进度。
5. 观察应用自有下载器写入 `.zip.part` 并报告真实字节进度；随后依次验证 ZIP 大小 / SHA-256、唯一 `apkEntryName`、APK 大小 / SHA-256、包身份和 APK 证书。ZIP 校验完成前不得解压，APK 校验完成前不得上传。
6. 解压 fixture 必须覆盖：空 ZIP、损坏 ZIP、缺少预期 APK、多个普通文件、多个 APK、嵌套 entry、`../` 路径穿越、输出超过 `apkSizeBytes`、ZIP CRC 错误和存储空间不足。任一反例都必须停止当前归档并清理 ZIP 与部分 APK。
7. 正常 fixture 必须确认 APK 校验通过后 ZIP 立即删除，APK 在当前安装会话内仍可用；安装会话成功、用户终止或“一键清理”后 APK 按生命周期删除。暂停 / 断线只允许复用相同清单版本的可信检查点。
8. 本轮只验证蓝奏根文件夹的解析、下载、ZIP / APK 校验和失败清理；R2 / GitHub 不参与当前版本判断，也不把它们的对象状态写成客户端通过条件。
9. 蓝奏云正式门禁覆盖真实密码根文件夹、实际 Android System WebView、目录替换后的版本识别、重复下载、切网、Range 续传和最终 URL 失效；用户已完成真实安卓手机人工下载 / 解压验证，后续不再把桌面浏览器或单纯 User-Agent 模拟当作客户端闭环证据。
10. 确认开始后，观察所有已选 APK 完成同一安装阶段；全部安装完成后只进入一次统一白名单授权阶段，最后仅启动 03 桌面进行运行验证，其他已选组件不得被启动。
11. 授权步骤必须能证明读取原值、幂等追加和回读一致，且不会覆盖已有通知或无障碍授权。
12. 完成后核对所有已选包名、版本、签名、统一授权回读、03 桌面进程 / 必要服务、其他已选组件安装存在性和脱敏错误日志；任一证据缺失不得显示“成功”。
13. 人为中断或断网，恢复连接后确认从最近检查点继续，旧结果不会覆盖新会话。
14. 在选择页 / 清单不可用页切到后台再回前台：车机仍在线时页面保持“已连接”，应用只做一次健康检查，不重新开始局域网扫描；车机断电或离开网络后回前台，必须报告连接丢失并提供重新连接入口。电脑上的其它 ADB 助手不作为本条证据，因为各客户端不共享连接列表。
15. 使用 Compose 可控时钟验证页面进入 `220ms`、退出 `180ms`、按钮按下 `90ms`、释放 `160ms`、状态变化 `160ms` 和进度追随 `180ms` 的中间帧与最终帧；任何状态不得从起始值直接跳到终值。
16. 运行级 smoke 录制或逐帧观察连接、选择、加载、下载进度、阶段完成、成功切入维护态的完整路径，确认所有进入 / 退出 / 点击 / 进度变化使用 `FastOutSlowInEasing`，同时不存在两套文字重叠、布局跳动或装饰性无限动画。

### 1.2 Debug 真实组件完整主链

1. **测试资料**：03桌面 `https://wwatl.lanzouw.com/iCdE743g9zve`、03歌词 `https://wwatl.lanzouw.com/ipRbT43g9zzi`、文件管理器 `https://wwatl.lanzouw.com/itMa843ga0la`；三份 ZIP 均在根目录只含一个 APK，身份资料位于 Debug `real-debug` 签名 profile，Release 不读取。
2. **前提**：手机已安装最新 Debug APK，手机与车机在同一局域网，车机 TCP `5555` 可达；Debug 分发配置验签成功且根文件夹可访问。若车机旧包不能保留数据覆盖，只有取得当次明确授权后才允许卸载对应精确包名。
3. **动作**：连接车机，保留必装的 03桌面，并按需选择 03歌词和文件管理器；点击开始安装后不操作网页，等待所有已选组件完成下载、ZIP / APK 校验和同一安装阶段；全部安装完成后执行一次统一授权计划，只启动 03 桌面。
4. **预期**：蓝奏云页面不可见，所有已选 ZIP 与 APK 身份全部校验通过；全部安装完成后车机实际已安装 APK 回读与清单一致；统一授权保留既有列表项并回读成功；03 桌面进程和必要 Service 可用，其他已选组件只报告安装存在，不被启动，最后才进入成功维护态。
5. **停止条件**：外部浏览器被打开、页面要求用户点击、HTML 被当作 ZIP、校验失败仍安装、全部安装未完成就授权、任一授权声明 / 回读失败仍继续、03 桌面无法启动或必要 Service 未绑定、其他已选组件被启动、或车机出现清单外包名。

## 2.1 F3 当前最小人工主测

1. **局域网发现**
   - 前提：手机已安装本轮 Debug APK；手机与当前目标车机处于同一局域网；车机 TCP `5555` 保持可达。电脑上的 ADB 助手是否同时连接不影响手机端扫描，二者不共享连接会话。
   - 动作：冷启动助手，观察其自动查找；将应用切到后台再切回前台，确认连接页再次自动查找；若列表出现车机，记录显示型号并选择该行。只有自动查找未触发或需要再次尝试时，才点击“重新查找”。
   - 预期：进入连接页先显示“正在查找车机”，随后只出现经过身份确认的设备；点击设备行后先显示“正在连接车机”，只有第二次真实 ADB 握手成功才进入选择页并显示“已连接到 <车机名称>”。回到前台时同样自动开始一次查找，不出现外部浏览器或第二个 ADB 工具界面。选择后迟到的旧扫描结果不会覆盖当前会话；在当前前台点击“停止查找”后不会立刻再次自启。
   - 停止条件：等待约 10 秒仍没有设备、出现无法理解的设备身份、应用崩溃，或出现未确认设备；停止该条并记录手机网络、车机网络和时间，不继续安装。
2. **正式 Cloud 缺失时的 fail-closed**
   - 前提：使用 Release 构建；项目 / Cloud 尚未提供正式 Android profile、公钥、组件映射和真实 ZIP / APK 身份资料。
   - 动作：等待清单加载结果，不反复点击“开始安装”，不把 Debug profile 当正式候选。
   - 预期：车机连接租约保持成功，页面显示“已连接到 <车机名称>”以及“暂时无法准备安装应用”，并提供“重新获取”；应用不打开蓝奏云、不启动下载或车机安装，也不显示“安装未完成，已保留可继续的进度”。
   - 停止条件：缺少正式签名清单仍进入组件下载 / 安装，或 Release 接受 Debug profile。
3. **Debug 蓝奏云真实链路**
   - 前提：使用本轮 Debug 构建及已验签的 `real-debug` profile。
   - 动作：按本矩阵 1.2 执行一次完整三组件主链；不再额外跑临时包或第二套安装专用流程。
   - 预期：清单验签、固定蓝奏云主源、隐藏 WebView、ZIP / APK 双重校验、车机安装、授权和可用性证据依次可观察；全部证据齐全前不进入成功态。
   - 停止条件：发布资料不全、WebView 可见 / 可触摸、来源顺序可被清单改写、校验失败仍安装，或任一敏感下载上下文被持久化。

## 3. 维护态主路径

1. 首次成功后重新打开，确认进入维护态且不再强制重复向导；背景仍为蓝色，不出现白底工具列表。
2. 确认常用、应用、存储与诊断三组均使用大号极简按钮：`360dp` 及以上为两列，`320dp` 至 `359dp` 为单列，按钮最小高度、文字换行、图标和边界均符合 UI 施工文案。
3. 逐项验证维护按钮按组错峰进入、按压、释放、页面进入和退出均有规定的非线性动画，没有静态出现、瞬间变色或点击无反馈。
4. 断开车机后确认只保留检查更新、一键清理和导出诊断；重新连接按钮进入一次有界发现，发现失败或停止仍停留在维护断线页。
5. 连接同一车机后确认回到维护态而不是首次安装选择页，原组件清单、已安装 / 配置 / 可用证据仍在；连接其它设备时停止并给出可重试的设备不一致结果。
6. 执行检查更新和保留数据重装，确认版本与数据边界正确；重装必须复用清单、下载、校验和安装主链，不默认清除数据。
7. 执行修复授权，确认只修改白名单目标并回读验证；动作运行中重复点击不能启动第二个动作。
8. 执行“管理已安装应用”，确认结果同时列出 03 桌面、03 歌词和文件管理器的安装状态；导出诊断确认内容脱敏且不包含 token、私钥、完整 shell 历史或用户媒体。
9. 卸载、清除数据、降级、重启和任意 shell 入口必须保持不可用；真实车机维护动作、断线恢复和冷启动人工主测在当前设备可用时执行，否则记录客观阻断。

8. 检查更新时确认清单版本、包签名和兼容范围先于下载；保留数据重装只复用已校验物，不默认清除数据。
9. 安装 / 卸载操作只允许受控组件和显式用户确认，未知包或任意 shell 入口必须保持不可用。

## 4. 设备与发布门禁

1. 物理设备测试必须显式传入唯一 `INSTALLER_TEST_ADB_SERIAL`，不得使用会枚举全部在线设备的入口。
2. 日常车机不是默认 instrumentation 目标；需要清数据、卸载、降级、重启或 release 安装时，必须取得用户当次明确授权。
3. 当前发布验证先覆盖配置签名、根目录集合、ZIP / APK 双哈希、ZIP entry、包签名、动态版本识别和蓝奏根文件夹主源；R2 / GitHub 若未来作为备用接入，需另行定义同一配置下的回滚用例；自有服务器 600GB/月额度不作为安装包直链主源验证目标。
4. 任一“必须通过”项失败即代表本轮代码不达标；不得删断言、降级安全门槛或以人工猜测替代证据。

5. OTG 测试必须单独记录手机 USB 角色、车机 USB 角色、ADB USB 枚举和权限结果；当前未形成证据前，不能把 OTG 失败算作 LAN 主链失败，也不能把存在接口算作支持。

6. 当前发布阻断测试：03桌面长期 Release 签名、03 歌词 production 发布身份和文件管理器 Debug / GPL 状态必须分别有可审计证据；任一缺失即停止公开发布。
