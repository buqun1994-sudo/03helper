# 03helper 验证矩阵

## 0. 当前验证口径

1. “最简自动化 + 用户人工主测”不等于跳过可测试产物：Android 工程变更必须先完成语法 / 编译、直接相关确定性单测、Debug APK 构建，并在显式测试设备可用时执行保留数据覆盖安装。
2. 覆盖安装后只执行已有、稳定、预计单条不超过 5 分钟且无破坏性动作或未具备外部前置的最小 smoke；复杂真实 WebView、真实 ZIP、切网、Range 续传、车机写入和长流程交给人工主测。若 smoke 框架会移除或替换目标包，必须在全部 smoke 结束后再次保留数据覆盖安装并核对包身份与启动入口，最终设备状态以最后一次安装为准。每条人工用例必须按设备前提、动作、预期结果和停止条件执行。任何 fixture 或模拟下载结果都不计为真实源通过。
3. 当前 Debug 主链验证 schema V4 签名配置、v3 无 Logo 历史兼容、动态 `apps[]`、Logo 元数据校验、内置 Logo 与本地 APK 图标缓存、Cloud 版本 / 大小展示、公共 `Download` 优先、蓝奏密码根文件夹枚举、未命中 ZIP 的下载 / 解压 / APK 身份读取，并按用户选择执行动态排序的批量安装、typed 授权和可用性完整主链。运行时不请求远程 Logo。公共 APK 和 ZIP 内 APK 的目标 `versionCode` / `versionName` 必须匹配签名配置；声明 ZIP（包括 desktop）可以缺失，未声明文件忽略，任一 APP 缺失 / 单项失败隔离；R2 / GitHub 不参与当前版本判断，Debug 结果不等于生产发布通过。
4. 设备离线、安装失败或不满足快速 smoke 门槛时，明确记录阻断或“待用户主测”；不因未执行复杂 smoke 阻断代码交付，但不得把它写成真实通过。

## 1. 低成本闭环

### 1.0 F3 直接自动化覆盖

1. `Ipv4Subnet` 必须排除网络地址和广播地址；`LanAdbDeviceDiscovery` 必须对重复候选和重复设备身份去重，并在有界并发、超时和取消后返回结构化结果。
2. `DeviceDiscoverySessionAdapter` 必须按同一事件端口发送设备确认和发现结束事件；点击设备后 `InstallationSession` 必须先进入 `CONNECTING`，只有持久在线连接适配器发出 `DeviceConnectionConfirmed` 才能进入 `CONNECTED`。
3. `InstallerRuntime` 必须在 `CONNECTED`、初始化阶段、成功结果和维护态持有同一连接租约；清单加载失败不得释放租约，只有维护页主动断开、重新发起发现、进程结束或健康检查确认掉线时释放。
4. Release 生产工厂在 Cloud V3 公钥或组件信任资料缺失时必须 fail closed；Debug 工厂只接受 schema 3、固定 keyId 和匹配的 `channel` / `environment` 签名配置，包名、证书和最低 SDK来自 APK 实际读取与本地发布者证书根。两者不能互相读取未授权信任资料。
5. `MainActivity` 首次创建和重新进入前台时必须通过 `InstallerRuntime.onForeground()` 自动启动一次发现；同一前台周期不得重复扫描，用户主动停止后不得立即自启。
6. 已核验 APK 必须与同一条连接租约交给 `DeviceInstallationCoordinator`；安装后必须拉回车机实际 APK 并核对包名与发布者证书，再进入授权阶段；版本、大小和 manifest SHA-256 作为观测证据保留，回读不可用进入待确认，包名 / 证书不一致才产生明确安装失败。
7. 授权声明校验必须发生在所有已选组件批量安装证据完成后、任何 app-op 或 secure settings 写入前；声明缺失时保留安装证据、授权写入次数为零。成功态必须同时具备所有已选组件安装证据、按签名 `apps[]` 生成的版本化授权计划回读证据、03 桌面启动 / 进程 / 必要 Service 证据以及其他已选组件安装存在性证据。
8. `MaintenanceController` 必须通过同一 `InstallationSession` 发布维护动作的 `RUNNING`、`SUCCEEDED` 或 `FAILED` 结果；同一时刻最多一个动作，车机动作无租约时必须结构化失败，检查更新、清理和诊断不得依赖车机连接。
9. `MaintenanceSessionStore` 必须拒绝损坏 JSON、未知 schema、非法来源 / 包身份 / 组件集合和超大记录；有效记录冷启动后只能恢复为 `MAINTENANCE + DISCONNECTED`，不能恢复活动动作或短时下载上下文。
10. 维护重连必须保留原清单、组件选择和安装 / 配置 / 可用证据；停止发现、无设备、设备不一致和握手失败回到维护断线态，同一设备确认后恢复维护态且不重新加载首次安装清单。
11. `InstallUiStateMapper` 与 `MaintenanceHome` 必须从快照投影维护反馈、断线动作禁用和受控组件安装状态，不在页面维护第二套状态机。
12. `InstallationBatchPlan` 的 `batchId` 与 `InstallationSessionSnapshot.sessionId` 必须分别覆盖业务尝试和适配器事件代次；重连 / 检查点恢复只改变事件代次，迟到旧代次事件不得改写当前快照，新批次必须重新冻结选择、可复用、准备和结果集合。（JVM 单测）
13. `FolderEntrySnapshotStabilizer` 必须在渐进 DOM 读取时累积规范化条目；目标 ZIP 未全部出现时只能返回 `Wait`，只有 `completeAtDeadline` 才能定案。用默认 `30_000ms` 外层超时和 WebView `48 x 200ms` 触发保护覆盖“非空不完整快照按 APP 局部失败、空快照超时”，不得提前报“下载目录中没有应用”。（目录适配器单测）
14. 结果聚合必须只读取当前 `InstallationBatchPlan.resultComponentIds`；连续两批选择不同组件时，上一批失败、维护库存和完整控制面清单都不得出现在下一批结果行或失败原因中；可复用应用只作为内部证据。（领域 / UI 投影单测）
15. 手机本地维护基线保存属于运行时外部副作用，只保存已验证安装身份；保存失败不可进入领域快照或 UI，安装、授权、可用性和车机库存结论保持不变。冷启动 / 重连必须依赖车机实时库存恢复；跨维护 action generation 的迟到回调不得改变当前结果。（运行时 / 领域单测）
16. `BoundServiceEvidenceParser` 必须同时识别完整服务组件名和 Android 9 `package/.ShortClassName` 缩写，并在 `4_096` 字符服务记录窗口内要求 `hasBound=true`；合法缩写、未绑定和读失败分别产生正确结构化结果，原始 `dumpsys` 文本不得进入领域或 UI。（设备适配器单测；当前样本车机只读 smoke）
17. `InstallationSessionEventDispatcher.isBatchActive(batchId)` 与 `DeviceInstallationCoordinator.executeBatch` 必须在首次写入、设备调用返回、后置授权返回和终态收据发送前执行批次活动检查；起始检查失活时 gateway 调用次数必须为 `0`，设备调用途中代次失活时不得发送旧批次收据。（应用 / 设备协调器 JVM 单测）
18. `DeviceInstallResult.Failed` 的同组件回读不确定原因在 `operationConfirmed` 时必须进入 `WRITE_CONFIRMED_PENDING_IDENTITY`；明确 `adb_pm_install_failed` 等写入失败必须压过矛盾的正面 identity evidence。（设备协调器 JVM 单测）
19. `isInstallAccepted` 必须拒绝所有 failure marker；`exitCode=0` 的 warning / 空输出可继续由身份回读裁决，非零退出码仅在独立 `Success` 行存在时接受。（设备适配器 JVM 单测）
20. 授权动态模式必须覆盖受信 staging package alias；内置组件包名偏离静态 canonical 时命令必须含 `--dynamic`、正确 typed action token，不能走旧硬编码分支。（授权命令 JVM 单测）
21. `InstallationBatchReceipt.validationFailure` 必须按组件隔离授权计划；可选组件 malformed setup 只能产生组件级授权失败，合法 desktop 仍可提交为 `READY`，被拒绝组件不得携带 authorization evidence。（领域 JVM 单测）
22. 受控包库存解析只能匹配签名配置 / 已验证 manifest 声明的包名及允许别名；必须证明不会调用 `pm list packages --user 0 -3` 枚举第三方包，未知包、系统包和路径不明的条目不得进入受控结果。（设备适配器 JVM 单测）
23. 管理页结果必须只在会话中保存受控应用状态，再由 `InstallUiStateMapper` 投影受控清单；列表阶段只消费包管理器 / `dumpsys` 轻量元数据，不自动拉取或解析 APK，四项受控 typed action 只能路由到当前受控组件，不得生成第三方 synthetic row 或进入授权 / 安装 / 任意 shell。（领域 / UI 投影 / 设备适配器 JVM 单测）
24. `ArtifactPreparationCoordinator` 必须把公共 `Download` 中身份可信但版本低于签名目标的 APK 视为未命中并继续远端解析；远端 APK 即使包名 / 证书正确，`versionCode` 或非空 `versionName` 与签名目标不一致也必须在 `ArtifactBatchPrepared` 前失败，且不得发布到公共 `Download`。（协调器 JVM 单测）

文档阶段还必须保持以下边界：计划中的测试不能被记录为已执行；没有真实设备、签名身份或发布源证据时，条目标记为“待验证 / 阻断”。

### 1.0.1 Cloud V2 历史字段与无密码配置（历史阶段）

本节只保留迁移审计记录，不能作为当前协议实现依据；当前协议以 `docs/protocols/android-helper-config-contract.md` 的 schema V4 为准，v3 仅作无 Logo 历史过渡。

1. V2 payload 必须显式包含 `previousVersionsUrl` 和 `previousVersionsPassword`，两字段缺失或未知字段都拒绝；空字符串表示未配置或无密码。
2. `previousVersionsUrl` 非空时只接受 HTTPS 蓝奏文件夹 URL：允许的蓝奏域名、单一 `b...` 文件夹路径、无用户名 / 密码、无 query、无 fragment；URL 为空时密码必须为空。
3. `folderPassword` 和 `previousVersionsPassword` 允许空字符串并按原样传递；空密码配置必须进入同一隐藏 WebView / 目录解析主链，不得因为密码为空提前失败。
4. `previousVersionsUrl` 在当前版本只作为签名配置中的未来人工入口数据，不能触发当前自动目录枚举、备用源切换或版本比较；未来手动选择流程必须另行做 APK 身份校验。
5. 当前 Debug staging 只接受 `keyId=03helper-staging-config-2026-08-22-v1`，算法为 `SHA256withECDSA` / P-256，内置公钥 SPKI SHA-256 为 `8c2573689e87e6c426add9f2249186ec7b6c0e8f44b196ea669c820adb1283d3`；旧 key 不兼容。
5. `expiresAt=2099-12-31T23:59:59.000Z` 作为当前长效配置的有效值通过；客户端仍必须拒绝早于或等于当前时间的配置。

## 1.1 F2 人工主测用例

以下用例是交付给用户的最小完整主测集。每条用例都必须在真实 Android 手机上执行；任一“停止条件”出现时停止该条，不把后续阶段猜测为成功。满足快速 smoke 门槛的启动与入口检查由 AI 先完成，复杂真实链路仍由用户主测。

发布资料的准备责任属于项目 / Cloud 发布方，不属于用户的测试动作。用户不需要自行寻找、生成、签发或上传 Android profile、公钥或组件 ZIP。AI 可以对本地仓库和已授权的公开资料做只读核对，但不能替发布方签发受信清单，也不能把缺失的发布资料伪造成可测试候选；资料未具备时只记录客观阻断。

1. **分发配置信任与根目录边界（发布门禁）**
   - 前提：由项目 / Cloud 发布方提供一份 schema V4 已签名 distribution-config（或明确标记为无 Logo 的 v3 过渡快照）、对应受信公钥、可访问的密码根文件夹和 `apps[]` 字段；声明 ZIP 可以缺失，但要准备公共 `Download` 命中或远端可下载的至少一个测试 APP。若签名配置或根文件夹资料尚未发布，用户不需要补齐，直接记录“外部发布前置阻断”并停止本条。
   - 动作：在候选资料具备后启动安装；确认客户端先验签配置，再在隐藏 WebView 中打开根文件夹并按 `apps[]` 声明文件名枚举。先只替换一个 ZIP 再检查一次，再同步更新签名配置中该 APP 的 `versionCode` / `versionName` / `apkSizeBytes` 与匹配 ZIP，观察选择页和后续 APK 校验的差异。
   - 预期：只有有效签名、未过期且字段完整的配置进入目录解析；根目录无法访问、密码错误或解析失败时整次拒绝；未声明文件忽略；声明 ZIP 缺失或重复只记录对应 APP，不能阻断其它 APP。选择页版本 / 大小只来自签名 `apps[]`；公共 APK 或 ZIP / APK 实际元数据必须同时匹配签名目标 `versionCode` / `versionName`、包名与发布者证书，其余大小 / 摘要作为证据。
   - 停止条件：签名错误仍进入下载、密码 / 短时 URL 被持久化、目录外文件被接受、只替换 ZIP 就改变选择页版本、或某一 APP 的缺失 / 重复阻断其它 APP。
2. **隐藏 WebView 回调**
   - 前提：安装助手 Debug / 候选包、Android System WebView 已更新，手机可访问签名配置指定的密码根文件夹。
   - 动作：从安装助手开始安装，观察整个根目录解析阶段；不点击页面、不切到浏览器；等待密码验证、文件枚举、下载回调、解析超时和页面失败各执行一次。
   - 预期：外部浏览器不启动，蓝奏云页面不出现在屏幕或最近任务，WebView 不接受触摸 / 焦点；成功回调后立即进入原生下载，失败或超时后 WebView 停止并销毁，用户只看到安装助手自己的进度。
   - 停止条件：出现外部浏览器、可见网页、需要用户点下载、或失败后 WebView 仍持续活动。
3. **私有 ZIP 下载、取消与恢复**
   - 前提：选择一个可观察长度的真实 ZIP，清单中的 ZIP 大小 / SHA-256 与对象一致。
   - 动作：下载中取消一次；在同一清单版本、同一来源类型下继续；再换成另一来源类型继续；检查应用私有缓存和用户可导出的诊断内容。
   - 预期：下载先写 `.zip.part`；取消保留可恢复部分和检查点；同一来源可发起 Range 续传，来源类型变化时从零开始；缓存 / 诊断不含短时 URL、Cookie 或 Referer。
   - 停止条件：把不同来源的字节拼接、取消后丢失或误用旧片段、或敏感上下文被持久化。
4. **目录整体一致性与更新识别**
   - 前提：根文件夹可包含或缺少 `apps[]` 声明的 ZIP，目录中未声明文件不影响解析；公共 `Download` 可提供本地 APK，实际下载的每个声明 ZIP 根目录只含一个 APK。
   - 动作：完成一次检查更新；先只人工替换其中一个 ZIP，再次执行检查更新；随后更新签名 `apps[]` 字段并提供匹配 ZIP；再分别加入未知文件、重复文件、缺失 desktop、错误 APK entry 和错误密码。
   - 预期：只有签名 `apps[]` 的版本 / 大小字段变化才更新选择页展示；仅替换 ZIP 不改变展示值，公共 APK 或 ZIP 内 APK 必须同时匹配签名目标 `versionCode` / `versionName`、包名与发布者证书才能生成当前 APP 的校验结果，大小 / 摘要作为证据。未知文件忽略，声明 ZIP 缺失或重复只生成对应 APP 失败并保留其它 APP；错误密码、根目录解析失败或签名配置失败才拒绝整次配置，不留下伪造的部分成功。
   - 停止条件：固定旧版本仍被错误缓存命中、只替换 ZIP 就改变选择页版本、某一 APP 失败导致安装页暂停、或错误配置仍进入选择页。
5. **ZIP 校验与受控解压**
   - 前提：准备确定性 ZIP fixture：正确 ZIP、大小错误、SHA-256 错误、损坏 ZIP / CRC 错误、空 ZIP、`../`、绝对路径、嵌套目录、多个 APK、额外普通文件和输出超出清单上限。
   - 动作：逐个替换当前来源对象并开始安装。
   - 预期：大小和 SHA-256 通过前绝不解压；只有根目录中清单指定的唯一 APK 可解压；任何反例都清理 ZIP、`.zip.part`、`.apk.part` 和无效 APK，并按固定源策略切换或停止。
   - 停止条件：校验失败仍创建 APK、路径穿越写出缓存根目录、接受第二个文件、或清理不完整。
6. **APK 身份校验与 ZIP 生命周期**
   - 前提：准备 APK 摘要正确 / 错误、包名错误、版本名或 versionCode 不同、签名证书摘要错误的 fixture；清单记录展示字段，客户端内置发布者身份作为准入真值。
   - 动作：逐个执行解压和身份校验，观察会话阶段和应用私有缓存。
   - 预期：目标 `versionCode` / `versionName`、包名和发布者证书全部通过后才产生产物验证成功事件；大小 / SHA-256 作为传输证据记录，不替代目标版本门禁；成功立即删除 ZIP，保留当前会话可用的已校验 APK；版本、包名或证书失败时清理 ZIP、部分 APK 和无效 APK。
