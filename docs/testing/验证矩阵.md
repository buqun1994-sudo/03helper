# 03helper 验证矩阵

## 1. 低成本闭环

| 变更类型 | 必须执行 | 覆盖结果 |
|---|---|---|
| 文档、规则、Skill、脚本 | `node scripts/check-project-docs.mjs`、`node scripts/check-skills.mjs`、`git diff --check` | 路由、底座结构、Skill 元数据和文本质量 |
| 领域 / 应用逻辑 | 语法或类型检查、直接相关单测 | 状态机、错误语义、取消与恢复 |
| 下载 / 清单 / 解压 | 确定性 fixture、ZIP / APK 双摘要反例、归档结构反例、网络失败测试 | 供应链完整性、受控解压、缓存清理与备用源边界 |
| ADB / 设备连接 | 假设备契约、定向 serial 快检、断线与超时 | 连接、取消、重连和设备隔离 |
| UI、启动、导航、输入 | 真实运行级 smoke、关键状态截图或可观察日志 | 用户主路径和错误态 |
| 安装 / 授权 / 维护 | 保留数据覆盖安装、版本 / 签名核对、最小设备 smoke | 包身份、授权回读、进程和服务可用性 |

文档阶段还必须保持以下边界：计划中的测试不能被记录为已执行；没有真实设备、签名身份或发布源证据时，条目标记为“待验证 / 阻断”。

## 2. 首次安装主路径

1. 冷启动助手，确认首屏是整屏 `#1976C5` 浅蓝背景，标题、说明、步骤、状态和进度内容以白色为主；首屏只显示首次安装入口和必要状态，助手本体不要求用户先整理其它 APK。
2. 让手机和当前样本车机处于同一局域网，确认有界发现、去重、显式设备选择和连接超时；记录 `S56_HQX`、Android 9、TCP `5555` 和 ADB 状态，不能把“端口可达”当作所有能力已打开。
3. 选择组件，确认 03 歌词和 03桌面不可取消，文件管理器可切换，版本、预计下载体积和兼容范围可见；用户界面不显示下载源、ZIP 路径或 APK 路径。
4. 让 `LanzouWebSourceAdapter` 用 Android System WebView 的默认手机端标识读取清单中的固定 ZIP 分享页，确认外部浏览器没有启动、蓝奏云页面不可见且无需用户点击即可取得最终 ZIP URL；页面解析阶段只显示安装助手自己的准备进度。
5. 观察应用自有下载器写入 `.zip.part` 并报告真实字节进度；随后依次验证 ZIP 大小 / SHA-256、唯一 `apkEntryName`、APK 大小 / SHA-256、包身份和 APK 证书。ZIP 校验完成前不得解压，APK 校验完成前不得上传。
6. 解压 fixture 必须覆盖：空 ZIP、损坏 ZIP、缺少预期 APK、多个普通文件、多个 APK、嵌套 entry、`../` 路径穿越、输出超过 `apkSizeBytes`、ZIP CRC 错误和存储空间不足。任一反例都必须停止当前归档并清理 ZIP 与部分 APK。
7. 正常 fixture 必须确认 APK 校验通过后 ZIP 立即删除，APK 在当前安装会话内仍可用；安装会话成功、用户终止或“一键清理”后 APK 按生命周期删除。暂停 / 断线只允许复用相同清单版本的可信检查点。
8. 模拟蓝奏云解析超时、无下载回调、HTML 假响应、ZIP 哈希不符、解压失败和 APK 哈希不符，确认自动切换到 R2 ZIP；再模拟 R2 不可达，确认继续切换到 GitHub Releases ZIP。夸克不能被客户端当作自动源。
9. 蓝奏云正式门禁覆盖真实单组件 ZIP、实际 Android System WebView、重复下载、切网、Range 续传和最终 URL 失效；用户已完成真实安卓手机人工下载 / 解压验证，后续不再把桌面浏览器或单纯 User-Agent 模拟当作手机端闭环证据。
10. 确认开始后，观察已校验 APK 的非流式推送、安装、白名单授权和启动验证均有可观察进度。
11. 授权步骤必须能证明读取原值、幂等追加和回读一致，且不会覆盖已有通知或无障碍授权。
12. 完成后核对包名、版本、签名、授权回读、目标进程 / 服务和脱敏错误日志；三类证据缺一不得显示“成功”。
13. 人为中断或断网，恢复连接后确认从最近检查点继续，旧结果不会覆盖新会话。
14. 使用 Compose 可控时钟验证页面进入 `220ms`、退出 `180ms`、按钮按下 `90ms`、释放 `160ms`、状态变化 `160ms` 和进度追随 `180ms` 的中间帧与最终帧；任何状态不得从起始值直接跳到终值。
15. 运行级 smoke 录制或逐帧观察连接、选择、加载、下载进度、阶段完成、成功切入维护态的完整路径，确认所有进入 / 退出 / 点击 / 进度变化使用 `FastOutSlowInEasing`，同时不存在两套文字重叠、布局跳动或装饰性无限动画。

## 3. 维护态主路径

1. 首次成功后重新打开，确认进入维护态且不再强制重复向导；背景仍为蓝色，不出现白底工具列表。
2. 确认常用、应用、存储与诊断三组均使用大号极简按钮：`360dp` 及以上为两列，`320dp` 至 `359dp` 为单列，按钮最小高度、文字换行、图标和边界均符合 UI 施工文案。
3. 逐项验证维护按钮按组错峰进入、按压、释放、页面进入和退出均有规定的非线性动画，没有静态出现、瞬间变色或点击无反馈。
4. 执行检查更新和保留数据重装，确认版本与数据边界正确。
5. 执行修复授权，确认只修改白名单目标并回读验证。
6. 打开高风险动作，确认影响说明、二次确认、取消和失败恢复完整。
7. 导出诊断，确认内容脱敏且不包含 token、私钥、完整 shell 历史或用户媒体。

8. 检查更新时确认清单版本、包签名和兼容范围先于下载；保留数据重装只复用已校验物，不默认清除数据。
9. 安装 / 卸载操作只允许受控组件和显式用户确认，未知包或任意 shell 入口必须保持不可用。

## 4. 设备与发布门禁

1. 物理设备测试必须显式传入唯一 `INSTALLER_TEST_ADB_SERIAL`，不得使用会枚举全部在线设备的入口。
2. 日常车机不是默认 instrumentation 目标；需要清数据、卸载、降级、重启或 release 安装时，必须取得用户当次明确授权。
3. 发布验证至少覆盖清单签名、ZIP / APK 双哈希、ZIP entry、包签名、版本回退、蓝奏云 ZIP 主源、R2 / GitHub Releases ZIP 自动备用和回滚指针；自有服务器 600GB/月额度不作为安装包直链主源验证目标。
4. 任一“必须通过”项失败即代表本轮代码不达标；不得删断言、降级安全门槛或以人工猜测替代证据。

5. OTG 测试必须单独记录手机 USB 角色、车机 USB 角色、ADB USB 枚举和权限结果；当前未形成证据前，不能把 OTG 失败算作 LAN 主链失败，也不能把存在接口算作支持。

6. 当前发布阻断测试：03桌面长期 Release 签名、03 歌词 production 发布身份和文件管理器 Debug / GPL 状态必须分别有可审计证据；任一缺失即停止公开发布。

## 5. 当前阶段人工确认状态

1. F1 的 Debug 场景和页面人工验收由用户明确跳过；该项不计作人工通过，也不得在进度文档中写成真实安装能力已验证。
2. F2 / F3 接入真实下载、WebView、局域网、ADB 和车机安装后，再把对应的真实功能用例交给用户；用例必须写清设备、动作、预期结果和停止条件，不得泛化为“整体回归”。
3. 在真实外部链路具备之前，自动化 fixture、单测和 Debug `flow` 只能证明状态机和页面投影，不替代真实源、真实 APK、真实设备或发布候选 smoke。
