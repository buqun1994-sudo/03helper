# 本地开发环境

## 0. 当前维护应用清单与授权验证

1. 维护应用清单依赖车机已安装的 03桌面桥接版本 2；助手不再使用逐包 `pm path` / `dumpsys` 作为全量列表回退。桥接查询返回完整批次收据，坏行或收据不符必须整体失败，禁止把部分结果交给用户。
2. 03桌面元数据与图标分离：先验证应用 rows，再按 `content://<authority>/icons/<packageName>` 获取图标。真实显示名称由 03桌面 PackageManager `loadLabel` 返回，排序使用 `firstInstallTime` 倒序。
3. 维护动作以 `packageName` 作为第三方应用身份；所有应用卡片在任一动作 RUNNING 时统一禁用。清数据、卸载、授权写入必须由用户当次确认，自动验证只做只读库存和协议检查。
4. 一键授权只对 APK 声明且助手具备固定适配器的项执行；每项执行“读原值 -> 写入 -> 回读”，单项失败继续后续项，最终按可自动处理项给出成功、部分成功或失败及原因。

## 1. 本机上下文入口

1. 私有配置文件是 `.codex/local-context.properties`，只参考 `.codex/local-context.properties.example` 创建，不提交。
2. 可能的键包括 JDK、Android SDK、ADB、独立测试设备 serial、共享工具链和版本清单入口；键值不写进仓库文档。
3. 进入构建或设备任务前先运行 `node scripts/check-local-environment.mjs`；脚本缺少本机配置时应明确失败，不猜路径。

## 2. ADB 与设备

1. 设备命令必须使用显式 serial，连接前记录设备型号、Android 版本、ADB 状态和目标包身份。
2. 局域网发现、USB / OTG 和无线调试是不同能力，分别验证，不把一种能力的成功外推到另一种。
3. 设备离线、认证未完成或状态未知时停止安装 / 授权，并保留可诊断错误。
4. 当前已测样本为 `S56_HQX`、Android 9，TCP `5555` 常驻开放，`ro.adb.secure=0`；这些数据只能用于当前适配夹具。首次连接前不承诺助手自动打开无线调试。
5. 局域网发现必须使用有界广播、去重、超时和停止条件；OTG 只有在手机 / 车机 USB 角色和 ADB USB 能力完成实证后才可进入正式主链。

## 3. 构建与安装

1. 安装助手是运行在用户手机上的现代 Android 应用，当前工程基线为 JDK 17、`compileSdk/targetSdk=36`、`minSdk=26`；关联项目面向 Android 9 车机的 `targetSdk` 策略不得复制到本应用。
2. 先执行与改动直接相关的最短检查，再构建目标变体；不要用全量构建掩盖未知错误。
3. Android 工程交付默认构建最新 Debug 产物并使用显式 serial 保留数据覆盖安装，确保用户拿到可测试前置；若 instrumentation 收尾移除目标包，必须在自动化结束后再次覆盖安装并核对启动入口；清除数据、卸载、降级、release 安装和重启必须当次授权。
4. 安装后至少核对版本、包名、签名摘要、进程 / 服务和致命日志；失败版本不得交给用户主测。
5. 安装助手主链对组件 APK 采用非流式推送：只有手机已完成清单、ZIP 大小与哈希、唯一 APK 解压、APK 大小与哈希、包身份和签名证书校验的完整文件才能上传到车机。
6. 授权动作必须先读原值、幂等追加并回读；重试只能复用可证明幂等的步骤，不得覆盖未知设置。

7. 维护应用管理读取 03桌面桥接提供的当前用户第三方应用完整元数据；不得把桥接当作控制通道，也不得在桥接失败时展示部分列表。应用操作继续只能通过固定 typed action 进入设备适配器，禁止任意 shell；写动作前重新复核包身份。

8. 助手自身更新只在共享制品准备完成后调用 Android 系统安装器；Android O 及以上必须检查 `REQUEST_INSTALL_PACKAGES` 对应的用户授权，拒绝时停在可重试的失败状态。安装器返回后不得仅凭 Intent 结果宣称成功，必须回读 `com.ninepointnine.helper` 的版本、大小、摘要和证书；系统安装界面显示“安装”或“更新”由 Android / 厂商决定，不作为客户端逻辑分支。

## 3.1 Android 身份、版本与签名

1. 正式 `applicationId` 与 `namespace` 固定为 `com.ninepointnine.helper`，Debug/staging 通过 `applicationIdSuffix=".test"` 派生测试包 `com.ninepointnine.helper.test`；源码包和 namespace 不变，不恢复历史 `com.tcrrry.helper`。
2. Debug/staging 测试包固定追加 `versionNameSuffix="-test"`，正式包保留正式版本名；四种构建都读取同一根目录 `release-version.properties` 的 `releaseVersionName` / `releaseVersionCode`，测试包与正式包共用版本码。
3. staging 构建显式传入 `helperSigningEnvironment=staging` 和 `helperStagingSigningPropertiesFile`；缺少 properties 或 JKS 必须在配置阶段失败，不得回落到 Debug 证书。
4. Release 固定使用仓库外独立 `03helper` production 证书，并继续从根目录 `release-version.properties` 读取版本；当前正式版本为 `1.0.10` / `versionCode=11`，测试包显示 `1.0.10-test` / `versionCode=11`。未指定版本时运行 `node scripts/bump-release-version.mjs` 递增 patch，明确指定时传入 `--version <major.minor.patch>`；每次递增这一份文件即可连续覆盖更新测试包。
5. Release 缺少 `helperProductionSigningPropertiesFile`、JKS 或字段时必须失败；staging 与 production 证书不得复用 03 桌面、03 歌词或彼此的身份。构建后使用 `apksigner verify --print-certs` 核对包名、单 signer、v2 和证书摘要。

## 4. 组件分发运维

1. 组件发布物由各产品仓库生成，03helper 只消费签名版本清单和审查过的 APK 元数据，不复制业务源码。
2. 当前分发顺序是签名配置（含 `versionCode` / `versionName` / `apkSizeBytes`）→ 蓝奏密码根文件夹定位；用户确认后每个 APP 先查手机公共 `Download`，仅复用匹配签名目标版本的 APK，再按需处理声明 ZIP。夸克仅人工 / 离线交付，自有服务器每月 600GB 流量不用于安装包直链主分发。
3. 每次候选发布按 `apps[]` 生成任意数量的单 APK ZIP，上传到同一个长期维护的受密码保护根文件夹；ZIP 推荐使用带版本的唯一文件名。服务端只签发展示信息、文件名、启用状态、安装策略、排序、能力门槛和 typed setup，包名、证书和最低 SDK 由客户端从 APK 读取并用本地发布者证书根校验。稳定且不超过 5 分钟的最小检查可由 AI 执行，复杂真实链路保留为人工门槛，最后才切换公开配置。
4. 动态根文件夹隐藏 WebView、ZIP 下载、解压、公共 `Download` 复用和版本字段展示 owner 已接入；Debug 使用 staging 公共入口，Release 固定请求 production 公共入口并只接受 schema v4、production/release、`SHA256withECDSA` 和已钉住 keyId。未声明文件忽略，任一 APP 缺失 / 单项失败隔离，desktop 最终失败只阻止进入维护。真实 production 根文件夹、Logo 公网对象、Android System WebView 下载与车机 smoke 完成前不得宣称生产下载链可用。

## 5. 发布与回滚

1. 发布前固定生成版本清单、哈希、签名摘要、兼容范围和回滚指针。
2. 上传先进入不可见或候选位置，校验和小范围 smoke 通过后再切换公开指针。
3. 任何发布、外部下载源切换、正式签名或生产配置变更都需要用户明确授权。
4. production APK / ZIP 和签名台账已就绪；公开切换前仍必须完成真实蓝奏入口、文件完整性、Logo 对象、GPLv3 源码 / 补丁 / 许可证入口、线上候选 smoke 和用户“上线”授权，不得把本地 revision 5 占位候选直接发布。
