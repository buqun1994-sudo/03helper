# 03helper 项目长期总纲

## 1. 项目定位

1. `03helper` 是独立的手机 Android 应用，面向普通用户提供 03 歌词、03桌面及经过审核的可选组件安装与维护编排。
2. 首次使用只暴露连接设备、选择组件和开始安装所需的界面；安装成功后进入维护态。
3. 安装助手不承载 03 歌词或 03桌面的业务逻辑，不改变它们的包名、签名或升级链；它只通过版本化组件清单和受控设备端口协作。
4. 前置分发默认只安装助手本体；组件由助手按签名版本清单获取。每个组件使用一个无密码蓝奏云单组件 ZIP 分享页作为国内自动主源，Cloudflare R2 和 GitHub Releases 镜像同一 ZIP 并依次自动兜底；密码聚合文件夹、三应用合并 ZIP 与夸克仅作人工 / 离线交付。Debug 变体已接入只含真实组件 Debug 包的本地签名验证 profile；正式 Cloud profile、发布对象和生产网络证据仍未具备。
5. 任何未完成实证的下载源、OTG 能力、系统授权或车机私有接口均记录为待验证，不写成正式能力。

## 2. 物理主链与 owner

### 2.1 已落地的 F0/F1 工程基座

1. Android 工程为单 `app` 模块；`applicationId` 与 `namespace` 均为 `com.tcrrry.helper`，组织前缀 `com.tcrrry` 沿用关联产品，`helper` 保持安装助手的独立包身份。当前版本为 `versionCode=1`、`versionName=0.1.0`。
2. 手机端采用现代 Android 基线：JDK 17、Gradle 8.11.1、Android Gradle Plugin 8.9.2、Kotlin / Compose plugin 2.1.0、`compileSdk/targetSdk=36`、`minSdk=26`。03 歌词和 03桌面仍以 Android 9 车机为运行目标；该限制不下沉为安装助手手机端的 `targetSdk`。
3. `app/src/main/kotlin/com/tcrrry/helper/domain/session/InstallationSessionState.kt`、`InstallationSessionSnapshot.kt`、`InstallationSessionCommand.kt` 与 `InstallationSession.kt` 定义并拥有唯一会话主链；快照包含会话代次、修订号、可恢复检查点和结构化证据，外部能力仍通过后续端口注入。
4. `app/src/main/kotlin/com/tcrrry/helper/ui/state/InstallUiStateMapper.kt` 是领域快照到首次安装 / 维护界面的唯一投影；`InstallApp.kt` 只消费该投影并分发 `InstallUiIntent`，页面不得直接持有 ADB、WebView、下载协议或第二套状态机。
5. `app/src/main/kotlin/com/tcrrry/helper/ui/theme/` 统一拥有颜色、尺寸、文字与非线性动效令牌；`ui/components/` 统一拥有 Lucide 图标解析、按压反馈、步骤指示和错峰进入；`ui/screens/` 只负责首次安装壳与维护按钮呈现。
6. `app/src/debug/kotlin/com/tcrrry/helper/debug/DebugScenarioActivity.kt` 提供确定性的 fake command / adapter event 场景，只存在于 Debug 变体，不进入 Release 清单；生产 `MainActivity` 创建同一个 `InstallationSession` 并以生命周期感知方式收集快照，不再硬编码静态 `IDLE` 快照入口。
7. F0 主源码清单不申请网络、存储、ADB、WebView、无障碍或其它业务权限；AndroidX 合并清单自动生成的签名级动态接收器权限属于框架产物，不代表助手获得业务能力。后续能力必须在对应阶段通过端口、适配器和最小权限评审后进入。

## 3. 安装会话状态

安装会话至少区分 `IDLE`、`DISCOVERING`、`CONNECTING`、`CONNECTED`、`SELECTION_CONFIRMED`、`RESOLVING_SOURCE`、`DOWNLOADING_ARCHIVE`、`VERIFYING_ARCHIVE`、`EXTRACTING_APK`、`VERIFYING_ARTIFACTS`、`INSTALLING`、`AUTHORIZING`、`VERIFYING_DEVICE`、`SUCCEEDED`、`PAUSED`、`FAILED` 和 `MAINTENANCE`。每个状态必须有进入原因、可执行动作、取消语义和恢复策略；未知状态只能停在安全失败态。

首次安装的用户边界固定为：

1. 用户动作只发生在“连接设备”和“选择 APK（含开始安装确认）”；发现后的连接握手、下载页解析、ZIP 下载与校验、APK 解压与校验、ZIP 删除、已选组件批量非流式推送与安装、一次固定综合授权、仅 03 桌面启动和快速验证由会话及应用适配器自动推进。
2. `CONNECTING` 只表示用户已选定候选且正在执行第二次真实 ADB 握手；只有 `DeviceConnectionConfirmed` 事件到达后才能进入 `CONNECTED`。`CONNECTED` 必须保存结构化设备身份、能力和应用层连接租约，不能因为端口可达就推断 OTG、无线调试开关或其它系统权限已可用。
3. `CONNECTED` 阶段清单加载失败只表示安装资料不可用：必须保留已确认设备、记录结构化原因并清除安装检查点，不能转成 `FAILED` 或显示可继续安装进度；用户只能从选择页重新获取清单。
4. 首次进入或重新回到前台且仍处于连接页时，应用自动派发一次有界设备发现；正在发现、连接握手、已连接选择、安装结果和维护态不重复启动扫描。持有连接租约时回到前台只做一次固定身份健康检查，不做常驻高频轮询；用户在当前前台主动停止后不立即自启。
5. APK 身份校验成功后会话停在 `VERIFYING_ARTIFACTS`；只有后续的 `InstallationStarted` 事件才能进入 `INSTALLING`。安装完成事件必须携带所有已选组件从车机已安装 APK 回读得到的大小、SHA-256、包名、版本和证书证据；随后才进入 `AUTHORIZING`，并在任何授权写入前校验 APK 权限 / Service 声明。`SUCCEEDED` 必须同时具备所有已选组件安装证据、一次统一授权回读证据、03 桌面启动 / 进程 / 必要 Service 证据和其他已选组件安装存在性证据，Debug 真实组件验证也不允许走安装专用成功态。
6. 成功后状态转入 `MAINTENANCE`，维护操作复用同一会话和命令白名单，不建立第二套安装状态机。

## 4. 长期不变量

1. 03桌面作为唯一核心组件由清单锁定且不可在首次安装页面取消；03歌词、文件管理器和其他扩展组件必须显式勾选并显示体积、来源和兼容范围。
2. 安装前必须完成设备身份、组件版本、签名摘要和哈希校验；任一校验失败不得继续上传或安装。
3. 所有授权动作都必须是版本化白名单，执行后必须回读；未知系统值不覆盖、不猜测。
4. 新请求取消旧会话，已成功步骤可复用；断线后从最近可靠检查点恢复，不重复执行不可幂等动作。
5. UI 只依赖结构化状态，不能根据日志文本猜测成功；成功必须同时满足所有已选组件安装、一次统一授权和 03 桌面可用性证据。
6. 维护态的更新、重装、清理、卸载和诊断动作按风险分级，破坏性操作默认关闭并二次确认。
7. 同一安装会话最多持有一个车机连接租约；清单缺失、组件取消或进入维护态不能隐式释放租约。只有维护页的“断开车机”、用户重新发起发现、进程结束，或健康检查确认车机客观掉线时才关闭租约；其它 ADB 客户端不共享也不替代该租约。
8. 远端清单只声明已签名发布物、哈希、包身份和兼容范围，不下发任意 shell、脚本或动态权限。
9. APK 在手机本地完成 ZIP 校验、受控解压和完整 APK 校验后才允许非流式推送；临时文件在会话结束或取消后按生命周期清理。
10. 首次安装和维护态共享蓝色整屏背景，用户可见状态只能通过统一的非线性动效令牌切换；页面、按钮、进度和结果不得各自复制或绕过第二套动画参数。

## 5. ZIP 发布物与缓存生命周期

1. `LanzouWebSourceAdapter` 必须使用 Android System WebView 默认手机端标识，在当前页面内执行正常分享页流程。下载回调归一为内存态 `ResolvedDownloadRequest`，至少携带最终 HTTPS URL、User-Agent、当次 Cookie、Referer、Content-Disposition、MIME 和页面可得的内容长度；原生下载器按需转交这些上下文，不把短时 URL 或 Cookie 写入清单、持久日志或诊断导出。
2. 每个自动组件发布物是一个单组件 ZIP：归档根目录只有一个普通文件，且文件名必须与清单的 `apkEntryName` 完全一致；不接受额外普通文件、嵌套目录、相对路径或多个 APK。
3. 清单分别声明 `archiveSizeBytes`、`archiveSha256`、`apkEntryName`、`apkSizeBytes`、`apkSha256`、包名、版本和证书摘要；ZIP 哈希和 APK 哈希不能互相替代。
4. 下载先写入应用私有缓存的 `.zip.part`。只有 ZIP 长度与摘要均通过后才允许进入解压；相同清单版本且来源支持 Range 时可恢复 `.zip.part`，其它情况删除后重新下载。
5. 解压前必须确认可用空间至少为 `archiveSizeBytes + apkSizeBytes + 64 MiB`。解压流写入 `.apk.part`，输出超过 `apkSizeBytes`、未找到预期 entry、遇到第二个普通文件或输出长度不等于 `apkSizeBytes` 时立即失败并清理。
6. APK 哈希、包名、版本和签名证书全部通过后，将 `.apk.part` 原子转为可安装 APK，并立即删除已校验 ZIP。解压或 APK 校验失败时同时删除 ZIP、`.apk.part` 和无效 APK，再按固定来源策略切换或停止。
7. 已校验 APK 仅保留给当前可恢复安装会话：安装、授权和可用性验证成功后删除；暂停或可恢复断线时保留，用户终止会话或执行“一键清理”时删除。ZIP 在成功解压后不进入维护缓存。
8. 解压使用 Android 平台自带 ZIP 能力，不要求手机文件管理器或额外解压 App；所有文件位于安装助手私有目录，用户不需要看到文件路径或授权通用存储访问。

## 6. 当前设备证据（非通用兼容承诺）

1. 当前样本车机为 `S56_HQX`、Android 9；实测 TCP `5555` 常驻开放，`ro.adb.secure=0`。
2. 这些值只能作为当前设备适配和验证夹具的事实，不能外推到其它型号或固件，也不能替代正式的设备能力探测。
3. 首次连接前不承诺由助手自动打开无线调试；当前固件无需额外开启即可评估局域网 ADB 主链。

## 7. 待决策与验证门槛

1. 单组件 ZIP 无密码蓝奏云适配器、本地签名 Debug profile 和完整下载 / 解压 / 安装编排已经接入；实际 Android System WebView、干净单 APK ZIP 和页面不可见性仍需在测试手机上完成运行证据。自有服务器 600GB/月不作为安装包直链主流量预算。
2. R2 与 GitHub Releases 的固定策略和本地镜像 fixture 已完成；真实对象的限流、断点和 ZIP / APK 双重版本一致性仍待人工验证。蓝奏云解析、下载、解压或校验失败时自动降级，不阻断全部安装流程。夸克只保留人工 / 离线交付。
3. 局域网发现与无线调试的可用固件范围须用真实设备验证；“自动打开无线调试”不能在未建立连接前被假定为可行。
4. OTG 是否进入 V1 取决于手机、车机 USB 角色和 ADB USB 能力的实证，不以接口存在推断能力。
5. 车机授权白名单、声明门禁、读前值、幂等写入和回读代码已经落地，但仍必须按目标 Android 版本和厂商状态逐项验证；任何安装失败、声明缺失、回读不一致或必要 Service 未绑定都必须安全停止。
6. 03桌面长期 Release 签名、03 歌词 production 发布身份和文件管理器正式分发 / GPL 义务尚未满足，是发布阻断项。
7. Cloud 已有官网、release index、R2、GitHub Releases 和 API 能力；03helper 只在 `docs/architecture/Cloud项目能力接线.md` 明确的 Android 适配边界内接入，不能假定 Cloud 已经发布 Android 组件清单。
