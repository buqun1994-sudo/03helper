# 代码规则

1. 触发条件：修改首次安装、维护模式或设备生命周期。动作：沿安装会话唯一状态机施工，UI、广播、脚本和适配器只派发事件或呈现状态，不复制决策。验证：状态转移单测、断点恢复和运行 smoke。边界：纯样式可留在呈现层。
2. 触发条件：新增设备发现或连接方式。动作：通过 `DeviceTransport` / `DeviceDiscovery` 等稳定端口隔离局域网、OTG 和 ADB 实现；适配器只返回结构化能力与错误，不把 socket、USB 或 shell 细节泄漏到 UI。验证：假设备契约、连接超时、取消和断线重连测试。边界：未实证的接口只能保留为实验适配器。
3. 触发条件：新增下载源、ZIP 解压或版本清单字段。动作：网页来源解析、HTTPS 下载、ZIP 校验、受控解压和 APK 身份校验各有 owner；下载源失败只触发已定义的备用源，不接受任意 URL 或远程命令。验证：篡改、过期、ZIP 结构异常、大小超限、版本回退和备用源 fixture。边界：UI 不解析供应商 JSON，也不直接操作 WebView 或归档文件。
4. 触发条件：新增授权或维护命令。动作：命令以版本化白名单和参数 schema 表达；执行前读取原值，执行后回读并记录结构化结果。验证：已授权、拒绝、部分成功、超时、取消和回滚测试。边界：不提供默认任意 shell 终端，不覆盖未知系统设置。
5. 触发条件：需要跨两个以上调用点复用规则。动作：回到现有 owner 或新增边界清晰的抽象。验证：调用点不再存在重复实现。边界：不为单次文案或样式新增抽象。
6. 触发条件：外部状态未知或协议字段缺失。动作：返回显式 `Unknown` / `Blocked` 结果并停止后续危险动作。验证：缺字段、旧版本、设备重启和网络切换 fixture。边界：禁止用猜测值把流程推进到安装或授权。
7. 触发条件：项目特有能力依赖的底层协议、格式或算法已有许可兼容且平台适配明确的成熟开源实现。动作：固定版本复用该实现，并只在项目端口中补业务策略、范围限制、结构化事件和安全门禁；不重新实现协议。验证：记录许可证与版本，执行直接集成测试、边界测试和目标产物构建。边界：不为了泛化评估批量引入替代依赖；维护状态、平台兼容或许可边界不明确时保持自有 fail-closed 适配或暂不接入。
8. 触发条件：外部资料、配置或清单在设备已连接或其它前置状态成立后不可用。动作：把资料不可用建模为当前前置状态的结构化阻断，保留已确认资源和重新获取入口，清除不适用的执行检查点；只有实际执行阶段失败才进入 `FAILED` / `PAUSED`。验证：覆盖“前置成立 + 资料失败”和“越序事件”两类状态转移测试，并确认 UI 不显示可继续执行的假进度。边界：签名、字段、身份或顺序校验失败仍必须 fail closed，不得为了保留连接而放行不可信资料。
9. 触发条件：连接页首次进入或重新回到应用前台。动作：通过应用编排 owner 自动触发一次有界设备发现；发现进行中、设备已连接、安装结果或维护态不得重复扫描，用户当前前台主动停止后不立即重启。验证：应用层生命周期入口测试、取消测试和前后台恢复人工用例。边界：不得用高频轮询代替生命周期触发，也不得绕过 `InstallationSession` 直接更新 UI。
10. 触发条件：为 Android 9 目标车机生成由 `sh` / `mksh` 执行的分隔字段授权动作。动作：禁止用包含 `|` 的参数删除模式拆字段；必须关闭 pathname expansion，以固定 `IFS` 拆分客户端生成的类型化元组，随后恢复 shell 状态并严格校验字段数、字段非空和动作白名单。验证：生成脚本语法检查、禁止旧参数删除模式的单测，以及 Android 9 真车合法动作 / 畸形动作 smoke。边界：只处理客户端生成的有界类型化字段，不接受远端或用户提供的任意 shell 文本，也不放宽授权白名单。
11. 触发条件：同一安装流程发生重连、取消后恢复或新一轮选择。动作：在 `InstallationBatchPlan` 中冻结业务 `batchId`、选择集、可复用集、准备集和结果集；把 `sessionId` 仅用于适配器事件代次，重连只换代次不换批次，迟到事件按代次 / 序列 / eventId 丢弃。验证：跨批次与跨代次状态转移、断线恢复和迟到事件单测。边界：不得用事件代次重建业务选择，也不得让 UI 或适配器自行生成第二份批次状态。
12. 触发条件：外部目录通过 WebView 分段或渐进返回。动作：在唯一目录适配器内累积规范化、去重后的快照；截止点前只返回等待，只有既有有界截止点才进行最终匹配，非空不完整快照按组件产生局部结果，空快照才判整体超时。验证：部分快照、重排、重复条目、截止点和空目录 fixture。边界：禁止以一次 DOM 读取或列表非空 / 非空缺失直接宣称下载目录缺少应用。
13. 触发条件：安装结果页需要展示当前尝试。动作：只用当前 `InstallationBatchPlan.resultComponentIds` 聚合结果和失败原因；维护基线、控制面全量清单与上一批结果只能作为内部证据，不得进入当前结果行。验证：连续两批不同选择、可复用组件和上一批失败污染的领域 / UI 单测。边界：不得在页面、异常分支或持久化读取中复制结果筛选规则。
14. 触发条件：成功安装或维护状态需要写入手机本地基线。动作：由 `InstallerRuntime` 在领域快照之外保存已验证安装身份；保存失败只记录诊断日志，不生成领域事件或 UI warning。下次启动 / 重连必须通过车机实时库存重新确认，领域 `sessionId` / generation 负责丢弃迟到适配器事件。验证：保存成功、保存失败不改写结果、冷启动实时库存恢复和跨 generation 迟到事件单测。边界：本地文件不得成为安装、授权或可用性结论的来源，也不得形成自动重试循环。
15. 触发条件：解析 Android 9 `dumpsys activity services` 的绑定证据。动作：集中在 `BoundServiceEvidenceParser` 同时匹配完整组件名和 `package/.ShortClassName`，并要求同一 `4_096` 字符记录窗口含 `hasBound=true`；领域只接收结构化布尔结果。验证：完整名、缩写名、未绑定、读失败和相邻服务干扰 fixture，外加当前样本车机只读 smoke。边界：不得在 shell、UI 或日志文本中增加平行字符串匹配，也不得把 ADB 连通或进程存在当作服务绑定。
16. 触发条件：完整业务数据与图标等渐进装饰读取共用同一串行设备或网络通道。动作：先整批校验并发布可操作的业务数据，再由应用编排 owner 启动独立、可取消的装饰任务；每个单项读取之间保留取消点，离开页面、刷新主数据、断连或开始前台操作时取消剩余队列，迟到结果继续经过当前会话代次门禁。验证：并发回归必须证明主数据先进入完成态、装饰读取能够渐进回写、前台操作会取消未完成队列并取得共享通道。边界：装饰失败不得降级完整业务结果，也不得建立第二套 UI 状态或绕过既有事件端口。
