# AI 协作规则

1. 触发条件：进入新对话。动作：先读根 `AGENTS.md` 和 `docs/README.md`，再按任务路由加载最小上下文。验证：方案和施工能引用当前磁盘 owner 与验证入口。边界：不一次性加载全部历史制造噪音。
2. 触发条件：磁盘文件与旧文案、截图或终端显示冲突。动作：以磁盘文件为真值并同步文档。验证：源文件 UTF-8 读取和相关快检。边界：不凭乱码或记忆重建中文内容。
3. 触发条件：同类判断重复出现。动作：使用 `rule-discovery` 沉淀规则、脚本、测试或 Skill。验证：后续入口能找到该能力。边界：一次性判断不升级为长期规则。
4. 触发条件：安装助手施工完成准备交付。动作：使用 `task-closeout` 汇总本机验证，构建并保留数据覆盖安装最新 Debug，按 5 分钟 / 已有入口 / 无破坏性动作 / 外部前置齐备的门槛选择最小 smoke；若 smoke 清理目标包，结束后再次覆盖安装并核对启动入口；剩余复杂链路交付精确人工用例。验证：版本、包身份、安装结果和已执行 / 待人工边界清楚。边界：不自动清数据、卸载、重启、提交、推送或发布。
5. 触发条件：发现跨项目通用能力。动作：使用 `template-feedback` 去专有化回流 `NewProject`。验证：模板源和当前项目各自检查通过。边界：不得把设备、下载源或业务协议污染模板。
6. 触发条件：用户下达普通功能施工且未明确要求完整代测。动作：按敏捷模式完成根因级实现，执行最短本机检查，交付可测试 Debug 并在显式设备可用时覆盖安装；只执行满足快速门槛的最小运行检查，其余真实场景整理为精确人工清单。验证：本机产物、安装结果和已执行 / 未执行范围可追溯。边界：敏捷不等于临时 Hack 或放宽安全边界。
7. 触发条件：用户完成主测。动作：有问题则继续修复并重新验证；无问题则等待用户明确下达提交指令。验证：提交范围与用户确认的实现一致。边界：用户只反馈“没问题”不等于授权提交、推送或发布。
