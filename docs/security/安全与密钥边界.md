# 安全与密钥边界

## 1. 密钥和配置

> 现行版本字段口径：签名配置中的 `versionCode`、`versionName`、`apkSizeBytes` 是选择页展示值，其中 `versionCode` / `versionName` 同时定义本次准备的目标版本；APK 必须精确匹配目标版本并通过包名与受信发布者证书校验，大小 / SHA-256 作为传输证据保留；旧 `versionLabel` / `sizeLabel` 与 `catalogVersion` 不参与应用版本展示。

1. 真实签名文件、私钥、密码、token、生产配置、设备地址和个人绝对路径不得进入 Git。
2. 客户端可公开的版本清单、公钥摘要和兼容元数据与服务端机密分开维护；客户端不保存发布私钥。
3. `.codex/local-context.properties`、`local.properties`、`keystore.properties` 和构建产物必须被忽略；提交前执行秘密扫描和 `git diff --check`。
4. 03helper 自身的签名身份、组件清单签名身份、03 歌词 production 身份和 03桌面 Release 身份必须分离管理；任何一个身份尚未建立，都不能用 Debug 包冒充正式信任根。
5. 当前 staging Android 配置签名信任根为 `03helper-staging-config-2026-08-22-v1`；production Release 固定为 `03helper-production-config-2026-08-30-v1`。两者均使用 `SHA256withECDSA` / P-256，但公私钥相互独立；Release 只接受 schema v4、production/release 和 production keyId，不回退到 staging / Debug。客户端只内置公钥，私钥必须留在仓库外受控存储并由 Cloud 运行时注入；配置加密密钥、配置签名私钥和 APK JKS 必须相互分离。
6. `03helper` 应用本身固定使用 `com.ninepointnine.helper`。Debug 使用开发机证书；staging 和 production 分别使用独立的仓库外 RSA 4096 证书，不能复用 03 桌面、03 歌词或对方环境的证书。仓库只保存 properties 字段布局与读取逻辑，不保存 JKS、口令、私钥或本机路径。
7. Release 版本真值只来自 `release-version.properties`，当前为 `1.0.6` / `versionCode=7`；未指定版本时只递增 patch，明确指定时接受完整 `major.minor.patch`。Debug / staging 版本不被 Release 文件覆盖，包名和对应环境证书必须在整个升级链中保持不变。

03helper 自身发布证书公开摘要（仅用于 Cloud / APK 校验，不是秘密）：

| 环境 | 包名 | 算法 / 密钥长度 | 证书 SHA-256 |
|---|---|---|---|
| staging | `com.ninepointnine.helper` | RSA / 4096 | `aca4f178fea11ccc97a1373c8aa5345b274a3a783398929a9340a79ee83663af` |
| production | `com.ninepointnine.helper` | RSA / 4096 | `31ca80dd21a5208eaabd5f3e1440a3db2f7dc79122e03eaa6ba01730fb31f18b` |

## 2. 下载与安装供应链

1. 首版主方案是“助手本体单独分发，组件按需获取”：客户端接受 Cloud schema V4 签名配置，并兼容读取没有 Logo 的 v3 历史快照，从中取得动态 `apps[]`、版本 / 大小字段和受摘要固定的 `icon` 元数据，选择页直接展示配置字段；Logo 二进制不在运行时从云端请求，初始化优先使用应用内置的最新资源。用户确认后先检查公共 `Download` 中通过包名、受信证书和签名目标版本的 APK，未命中才通过受密码保护的蓝奏根文件夹获取 ZIP，再从 APK 读取包名、版本、发布者证书和图标；通过身份校验的 APK 图标按组件、版本和 APK 摘要持久化并覆盖内置预览，大小和 SHA-256 只保留为传输证据。
2. 根文件夹地址、密码、`apps[]` 展示信息 / 安装策略 / 排序 / 能力门槛和 typed `deviceSetup` 属于签名配置；密码字段为空字符串表示无密码，包名、证书、最低 SDK 和 APK 实际 entry 不由网络覆盖，而由客户端读取并用官方发布者证书根校验。密码只在本次加载和下载期间存在于内存，不写入日志、崩溃信息、缓存、诊断、Git、埋点、Cookie 或 Referer。人工先把新增或替换后的 ZIP 上传到同一个长期维护入口并完成预检，再发布完整签名配置即可新增或更新 APP；客户端不依赖固定 APP 数量、索引或短时直链。
3. 蓝奏云只允许安装助手自己的隐藏 Android System WebView 适配器访问签名配置指定的根文件夹；不调用第三方“直链转换器”，不打开外部浏览器，也不把页面内容或最终地址展示给用户。自有服务器每月 600GB 流量不作为安装包直链主预算。
4. 下载只接受 HTTPS 和受信任配置；必须校验配置签名、有效期、`environment + channel`、`catalogRevision` 单调性、根文件夹集合、声明 ZIP 结构、APK 目标版本、包名和签名证书摘要。大小与 SHA-256 仍用于传输完整性证据，不替代版本门禁。配置不能携带任意 shell、脚本、动态权限、包身份字段或任意包体 URL。当前长效配置使用 `2099-12-31T23:59:59.000Z`，客户端仍拒绝已过期值。
5. ZIP 必须完整下载并校验后才能解压；解压必须只产生清单指定的唯一 APK。APK 完成包名 / 发布者证书最小身份校验后，先发布到公共 `Download` 再向车机做非流式推送；大小与摘要作为证据记录，成功后删除 ZIP，失败、取消或过期的私有临时文件按生命周期清理。
6. 配置签名 / 修订回退、清单过期、源不可达、APK 目标版本不符或包身份不符时 fail closed，并向用户给出可理解的下一步；大小与摘要继续作为传输证据，不单独替代版本和身份校验。

### Debug 真实组件验证边界

1. `app/src/debug/assets/real-debug/` 中的公钥与源码内真实组件 Debug 身份只属于 Debug 变体；它们用于 F3 完整工程闭环，不是 Cloud 正式 profile、生产信任根或公开发布候选。
2. Debug 变体与 Release 变体共用同一完整主链：下载、ZIP 校验、受控解压、APK 身份校验、已选组件批量 `pm install -r`、安装后 APK 拉回核验、按签名 `apps[]` 生成的版本化授权计划和仅 03 桌面可用性验证。不存在远端可开启的安装专用模式，也不能跳过授权 / 安装存在性 / 03 桌面可用性证据进入成功维护态。
3. Release 变体不读取 Debug profile；正式 Cloud profile、公钥或对象缺失时保持 fail closed。远端清单、蓝奏云链接和用户输入都不能把 Debug 资料带入 Release。
4. Debug ZIP 仍是外部不可信输入：归档根目录必须只有一个清单指定 APK，不接受 `__MACOSX`、目录或第二个 entry；每次更换 ZIP 都必须重新核验传输大小 / 摘要，并重新读取包名、目标版本与发布者证书身份，版本不匹配时不得进入安装。

### 蓝奏云 ZIP 特殊边界

1. 密码根文件夹地址指向网页，不等于任何 ZIP 对象地址；客户端在安装进度页背后用 Android System WebView 完成密码验证、枚举和当次文件下载回调，再交给应用自有原生下载器，不手工复刻隐藏字段或依赖第三方服务。
2. WebView 使用默认手机端标识，不改成桌面 User-Agent；不暴露应用 JavaScript bridge、设备文件或 ADB 能力。解析超时、未触发下载、最终响应为 HTML / JSON 或域名不在适配器允许范围时，立即终止本次配置加载并清理临时上下文。
3. 根文件夹不设业务 APP 数量上限，只受配置体积和字段长度护栏约束；客户端只处理启用 `apps[]` 声明的 ZIP，未声明文件直接忽略。声明 ZIP 可以缺失，因为用户公共 `Download` 可能已有匹配 APK；实际处理的每个 ZIP 必须只能包含一个根目录 APK，最终 ZIP 响应仍必须经过 HTTPS、大小上限、超时 / 取消和本地官方发布者证书根校验。任一 APP（包括 `desktop`）失败只标记该 APP，不阻断其它 APP；只有结果页在 `desktop` 无可用证据时隐藏维护入口。
4. 页面验证后产生的 `zipN.webgetstore.com` 地址、Cookie 和 Referer 只在内存中交给原生下载器；不写入配置、持久缓存、日志或诊断。页面改版、限流或密码错误只应形成结构化配置失败，不能降级为未校验来源。

## 3. ADB 与系统授权

1. ADB 命令使用版本化白名单和参数 schema；不提供默认任意 shell 入口，也不让远端清单下发命令文本。`deviceSetup` 只能映射到客户端预定义的 typed action。
2. 写入系统设置前读取原值，按白名单幂等追加，执行后回读并比较；未知值不覆盖，失败不静默，不删除车机已有通知或无障碍服务授权。
3. 首次连接前不承诺自动打开无线调试。当前样本 `S56_HQX` 为 Android 9、TCP `5555` 常驻开放且 `ro.adb.secure=0`，仅作为已测设备事实，不能当作通用安全或兼容承诺。
4. 新增 Android 权限、无障碍服务、文件访问或网络域名必须记录用户价值、版本边界、最小权限、拒绝后的功能退化和验证方式，不能因为“安装更方便”无限扩大权限。当前声明 `android.permission.INTERNET` 用于清单、固定来源 HTTPS 对象流和用户主动发起的局域网 TCP ADB 身份探测；仅在 Android 9 及以下申请 `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE`，用于读取和写入用户公共 `Download`，Android 10 及以上通过 `MediaStore.Downloads` 发布和扫描，不申请全盘管理权限。`android.permission.REQUEST_INSTALL_PACKAGES` 仅用于 `03helper` 自身更新调用系统安装器，受 Android O+“允许安装未知应用”用户授权约束；用户拒绝时必须保留结构化失败、重试和系统设置入口，不得借此浏览或静默安装任意第三方 APK。其它权限拒绝时保留应用运行并把公共 APK 复用降级为不可用，不能伪造命中。

5. 维护应用管理只接受签名配置 / 已验证 manifest 中声明的受控组件包名及允许别名；先读取受控包的轻量包管理器 / `dumpsys` 元数据，不执行 `pm list packages --user 0 -3`，不枚举或展示第三方包。应用详情只能由用户明确触发，并返回当前受控包的结构化版本、时间、UID、路径等信息；任何包身份不匹配或路径不在受控校验范围内都必须丢弃，不能把未知包带入展示清单。

6. 受控行的设备操作只允许用户主动触发的四种固定 typed action：`START`、`FORCE_STOP`、`UNINSTALL`、`DETAILS`。每次动作在执行前重新读取并校验受控组件包名 / 证书身份；启动只解析并启动受控包自己的 launcher，强停只调用目标受控包，卸载必须以包消失回读为后置条件，详情只返回结构化包元数据。未知或第三方包不接受任何管理动作，不进入授权 / 安装主链，不接受任意 shell、远端命令或路径参数。

7. F3 的 TCP ADB 协议层固定复用 Apache-2.0 `dev.mobile:dadb:1.2.9`；发现与连接只读取固定设备身份，设备动作阶段只通过项目白名单网关执行固定推送路径、安装、身份回读、授权和可用性命令。库的 root 或任意 shell API 不向应用层、UI、清单或用户输入暴露。
8. 授权声明校验位于安装身份核验之后、任何 app-op 或 secure settings 写入之前；声明缺失时保留“已安装”证据并安全停止授权。Android 9 先读取现有安全列表并做条目 / 序列化容量预检，写入后回读且保留既有条目。部分授权动作失败时不得伪造整批授权成功。
9. 安装阶段不得启动任何目标应用；全部选定组件安装并完成安装证据后，按签名 `apps[]` 动态生成一次版本化授权计划，运行验证只允许启动 03 桌面。

## 4. 数据与日志

1. 只收集完成安装所需的最少设备信息；不读取媒体、通讯录、车辆控制数据或无关文件。应用管理页只保留当前受控组件的包名、版本、安装时间、更新时间、APK 路径和 UID 观测，不读取或保存应用数据，也不保存或展示第三方包。
2. 日志只记录阶段、错误类别、非敏感设备标识和版本；诊断导出由用户主动触发并默认脱敏。
3. 不保存完整 shell 历史、私钥或可重放的授权令牌；ZIP、分片、解压中的 APK 和 MediaStore 临时读取副本按生命周期清理，不得在应用私有目录保留完整 APK；已校验 APK 只保留在公共 `Download`，一键清理只删除助手生成的 `03helper-` 文件。受控应用观测不写入可替代实时证据的持久化结论，冷启动后必须重新读取车机受控库存。

## 5. 高风险动作

清除数据、卸载、降级、重启、修改签名、发布、切换生产下载源和公开切换版本清单都必须取得用户当次明确授权；普通 debug 安装和最简 smoke 不自动扩大到这些动作。

## 6. 发布阻断

1. 四个 03 APP 与 Fossify 车机适配版的 production APK / ZIP、独立签名和本地台账已经核验，不再以 Debug 身份进入正式候选。
2. Fossify 仍是 GPLv3 第三方开源组件；公开提供修改版二进制时必须同时提供固定上游提交、完整补丁和许可证入口，不得声称 Fossify 官方签名或发布身份。
3. 当前剩余 production 阻断是：真实蓝奏入口、所声明 APP 的 ZIP 上传与文件完整性、Logo 公网对象、线上候选 smoke 和用户“上线”授权。revision 5 占位候选保持 `local-only` / `publishable=false`，不得直接写入线上配置。
