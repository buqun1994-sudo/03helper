# 安全与密钥边界

## 1. 密钥和配置

1. 真实签名文件、私钥、密码、token、生产配置、设备地址和个人绝对路径不得进入 Git。
2. 客户端可公开的版本清单、公钥摘要和兼容元数据与服务端机密分开维护；客户端不保存发布私钥。
3. `.codex/local-context.properties`、`local.properties`、`keystore.properties` 和构建产物必须被忽略；提交前执行秘密扫描和 `git diff --check`。
4. 03helper 自身的签名身份、组件清单签名身份、03 歌词 production 身份和 03桌面 Release 身份必须分离管理；任何一个身份尚未建立，都不能用 Debug 包冒充正式信任根。
5. 当前 staging Android 配置签名信任根为 `03helper-staging-config-2026-08-22-v1`（`SHA256withECDSA` / P-256）；客户端只内置公钥，私钥必须留在仓库外受控存储并由 Cloud 运行时注入。旧信任根已废弃，不做双 key 兼容；配置加密密钥必须与签名私钥分离。

## 2. 下载与安装供应链

1. 首版主方案是“助手本体单独分发，组件 ZIP 延迟下载”：客户端只接受 Cloud schema V3 签名配置，从中取得一个受密码保护的蓝奏根文件夹和动态 `apps[]` 目录声明，逐项枚举当前 ZIP 并从 APK 内读取版本、大小、SHA-256、包名、最低 SDK 和证书，再完成 ZIP 与 APK 双重校验后安装。
2. 根文件夹地址、密码、`apps[]` 展示信息 / 安装策略 / 排序 / 能力门槛和 typed `deviceSetup` 属于签名配置；密码字段为空字符串表示无密码，包名、证书、最低 SDK 和 APK 实际 entry 不由网络覆盖，而由客户端读取并用官方发布者证书根校验。密码只在本次加载和下载期间存在于内存，不写入日志、崩溃信息、缓存、诊断、Git、埋点、Cookie 或 Referer。人工先上传一批不可变 ZIP、完成预检，再发布配置即可新增或更新 APP，客户端不依赖固定 APP 数量、索引或短时直链。
3. 蓝奏云只允许安装助手自己的隐藏 Android System WebView 适配器访问签名配置指定的根文件夹；不调用第三方“直链转换器”，不打开外部浏览器，也不把页面内容或最终地址展示给用户。自有服务器每月 600GB 流量不作为安装包直链主预算。
4. 下载只接受 HTTPS 和受信任配置；必须校验配置签名、有效期、`environment + channel`、`catalogRevision` 单调性、根文件夹集合、声明 ZIP 结构、APK 大小与 SHA-256、包名、签名证书摘要、版本和兼容范围。配置不能携带任意 shell、脚本、动态权限、包身份字段或任意包体 URL。当前长效配置使用 `2099-12-31T23:59:59.000Z`，客户端仍拒绝已过期值。
5. ZIP 必须完整下载并校验后才能解压；解压必须只产生清单指定的唯一 APK。APK 完成大小、哈希、包身份和证书校验后，才允许向车机做非流式推送；成功解压后立即删除 ZIP，失败、取消或过期文件按生命周期清理。
6. 校验失败、签名不一致、版本回退、清单过期、源不可达或包身份不符时 fail closed，并向用户给出可理解的下一步。

### Debug 真实组件验证边界

1. `app/src/debug/assets/real-debug/` 中的公钥与源码内真实组件 Debug 身份只属于 Debug 变体；它们用于 F3 完整工程闭环，不是 Cloud 正式 profile、生产信任根或公开发布候选。
2. Debug 变体与 Release 变体共用同一完整主链：下载、ZIP 校验、受控解压、APK 身份校验、已选组件批量 `pm install -r`、安装后 APK 拉回核验、按签名 `apps[]` 生成的版本化授权计划和仅 03 桌面可用性验证。不存在远端可开启的安装专用模式，也不能跳过授权 / 安装存在性 / 03 桌面可用性证据进入成功维护态。
3. Release 变体不读取 Debug profile；正式 Cloud profile、公钥或对象缺失时保持 fail closed。远端清单、蓝奏云链接和用户输入都不能把 Debug 资料带入 Release。
4. Debug ZIP 仍是外部不可信输入：归档根目录必须只有一个清单指定 APK，不接受 `__MACOSX`、目录或第二个 entry；每次更换 ZIP 都必须重新核验并重签大小、摘要、包名、版本和证书。

### 蓝奏云 ZIP 特殊边界

1. 密码根文件夹地址指向网页，不等于任何 ZIP 对象地址；客户端在安装进度页背后用 Android System WebView 完成密码验证、枚举和当次文件下载回调，再交给应用自有原生下载器，不手工复刻隐藏字段或依赖第三方服务。
2. WebView 使用默认手机端标识，不改成桌面 User-Agent；不暴露应用 JavaScript bridge、设备文件或 ADB 能力。解析超时、未触发下载、最终响应为 HTML / JSON 或域名不在适配器允许范围时，立即终止本次配置加载并清理临时上下文。
3. 根文件夹不设业务 APP 数量上限，只受配置体积和字段长度护栏约束；客户端只处理启用 `apps[]` 声明的 ZIP，未声明文件直接忽略，desktop ZIP 必须存在，任意可选 APP ZIP 可以缺失。实际处理的每个 ZIP 必须只能包含一个根目录 APK；最终 ZIP 响应仍必须经过 HTTPS、大小上限、超时 / 取消和本地官方发布者证书根校验。单个可选 APP 失败只标记该 APP，不阻断其它 APP。
4. 页面验证后产生的 `zipN.webgetstore.com` 地址、Cookie 和 Referer 只在内存中交给原生下载器；不写入配置、持久缓存、日志或诊断。页面改版、限流或密码错误只应形成结构化配置失败，不能降级为未校验来源。

## 3. ADB 与系统授权

1. ADB 命令使用版本化白名单和参数 schema；不提供默认任意 shell 入口，也不让远端清单下发命令文本。`deviceSetup` 只能映射到客户端预定义的 typed action。
2. 写入系统设置前读取原值，按白名单幂等追加，执行后回读并比较；未知值不覆盖，失败不静默，不删除车机已有通知或无障碍服务授权。
3. 首次连接前不承诺自动打开无线调试。当前样本 `S56_HQX` 为 Android 9、TCP `5555` 常驻开放且 `ro.adb.secure=0`，仅作为已测设备事实，不能当作通用安全或兼容承诺。
4. 新增 Android 权限、无障碍服务、文件访问或网络域名必须记录用户价值、版本边界、最小权限、拒绝后的功能退化和验证方式，不能因为“安装更方便”无限扩大权限。当前仅声明 `android.permission.INTERNET`，用于清单、固定来源 HTTPS 对象流和用户主动发起的局域网 TCP ADB 身份探测；不新增存储、无障碍或定位权限。拒绝或网络范围不可用时保持发现 / 下载 fail-closed。

5. F3 的 TCP ADB 协议层固定复用 Apache-2.0 `dev.mobile:dadb:1.2.9`；发现与连接只读取固定设备身份，设备动作阶段只通过项目白名单网关执行固定推送路径、安装、身份回读、授权和可用性命令。库的 root 或任意 shell API 不向应用层、UI、清单或用户输入暴露。
6. 授权声明校验位于安装身份核验之后、任何 app-op 或 secure settings 写入之前；声明缺失时保留“已安装”证据并安全停止授权。Android 9 先读取现有安全列表并做条目 / 序列化容量预检，写入后回读且保留既有条目。部分授权动作失败时不得伪造整批授权成功。
7. 安装阶段不得启动任何目标应用；全部选定组件安装并完成安装证据后，按签名 `apps[]` 动态生成一次版本化授权计划，运行验证只允许启动 03 桌面。

## 4. 数据与日志

1. 只收集完成安装所需的最少设备信息；不读取媒体、通讯录、车辆控制数据或无关文件。
2. 日志只记录阶段、错误类别、非敏感设备标识和版本；诊断导出由用户主动触发并默认脱敏。
3. 不保存完整 shell 历史、私钥或可重放的授权令牌；缓存和临时 APK 按生命周期清理。

## 5. 高风险动作

清除数据、卸载、降级、重启、修改签名、发布、切换生产下载源和公开切换版本清单都必须取得用户当次明确授权；普通 debug 安装和最简 smoke 不自动扩大到这些动作。

## 6. 发布阻断

1. 03桌面尚无长期 Release 签名，不能进入正式分发清单。
2. 03 歌词尚未建立 production 发布身份，不能以当前开发包作为公开升级根。
3. 文件管理器仍为 Debug 身份，且正式分发需履行 GPL 义务；在身份和义务未完成前只能保留为待审核可选项。
