# 安全与密钥边界

## 0. 当前维护应用桥接边界

1. 03桌面桥接是只读 `ContentProvider`，只返回当前用户的第三方应用元数据和按包名读取的图标，不提供启动、停止、卸载、清数据或授权命令。助手通过 `protocolVersion=2`、批次数量和 SHA-256 收据拒绝不完整响应。
2. 正式包、测试包和历史包即使共享组件语义，也按实际 `packageName` 独立展示和操作；任何包名 / 启动组件不一致都在适配器边界失败。
3. 一键授权采用类型化白名单：危险 runtime permission、固定 AppOp、声明的本包无障碍 / 通知服务；普通 / 签名权限仅展示状态，不伪装成可写授权。每个写项均回读，secure 列表保留既有条目并受容量限制。

## 1. 密钥和配置

> 现行分发口径：Cloud V5 签名配置决定应用和批准的 APK 身份；选择页显示规范化版本与体积。公共缓存和下载 APK 的包名、完整当前证书集合、versionCode、versionName、字节数及 SHA-256 必须全部精确匹配。详见 `docs/protocols/android-helper-config-contract.md`。

1. 真实签名文件、私钥、密码、token、生产配置、设备地址和个人绝对路径不得进入 Git。
2. 客户端可公开的版本清单、公钥摘要和兼容元数据与服务端机密分开维护；客户端不保存发布私钥。
3. `.codex/local-context.properties`、`local.properties`、`keystore.properties` 和构建产物必须被忽略；提交前执行秘密扫描和 `git diff --check`。
4. 03helper 自身的签名身份、组件清单签名身份、03 歌词 production 身份和 03桌面 Release 身份必须分离管理；任何一个身份尚未建立，都不能用 Debug 包冒充正式信任根。
5. 当前 staging Android 配置签名信任根为 `03helper-staging-config-2026-08-22-v1`；production Release 固定为 `03helper-production-config-2026-08-30-v1`。两者均使用 `SHA256withECDSA` / P-256，但公私钥相互独立；Release 只接受 schema V5、production/release 和 production keyId，不回退到 staging / Debug。客户端只内置公钥，私钥必须留在仓库外受控存储并由 Cloud 运行时注入；配置加密密钥、配置签名私钥和 APK JKS 必须相互分离。
6. `03helper` 正式包固定使用 `com.ninepointnine.helper`，Debug/staging 测试包固定使用 `com.ninepointnine.helper.test`；Debug 使用开发机证书，staging 和 production 分别使用独立的仓库外 RSA 4096 证书，不能复用 03 桌面、03 歌词或对方环境的证书。仓库只保存 properties 字段布局与读取逻辑，不保存 JKS、口令、私钥或本机路径。
7. 所有变体的版本真值只来自 `release-version.properties`，测试版本名追加 `-test`，版本码与正式变体相同；未指定版本时只递增 patch，明确指定时接受完整 `major.minor.patch`。测试包与正式包分别保持各自包名和对应环境证书，递增同一版本文件即可连续覆盖更新测试包；实际交付版本及核验结果记录在 `docs/progress.md`。

03helper 自身发布证书公开摘要（仅用于 Cloud / APK 校验，不是秘密）：

| 环境 | 包名 | 算法 / 密钥长度 | 证书 SHA-256 |
|---|---|---|---|
| staging | `com.ninepointnine.helper.test` | RSA / 4096 | `aca4f178fea11ccc97a1373c8aa5345b274a3a783398929a9340a79ee83663af` |
| production | `com.ninepointnine.helper` | RSA / 4096 | `31ca80dd21a5208eaabd5f3e1440a3db2f7dc79122e03eaa6ba01730fb31f18b` |

## 2. 下载与安装供应链

1. 助手本体单独分发，组件按 Cloud V5 获取。签名配置批准的包名、完整当前证书集合、版本、大小和 APK SHA-256 是准备与安装的同一核验目标；本地缓存不满足任一条件即视为未命中，远端不匹配文件不得安装或发布到公共 Download。未知发布者不需要客户端更新。
2. Cloud V5 只下发目录、展示与安装策略及批准的 APK 身份；客户端核对实际包名、完整当前证书集合、版本、大小和 SHA-256。最低 SDK 与权限声明从 APK 读取，不接受远端 shell 或动态设置名。 密码仅在加载与下载内存中使用，不进入日志、维护基线、诊断或 Git。先上传并核对 ZIP，再发布启用快照；客户端不依赖固定 APP 数量。
3. 蓝奏云只允许安装助手自己的隐藏 Android System WebView 适配器访问签名配置指定的根文件夹；不调用第三方“直链转换器”，不打开外部浏览器，也不把页面内容或最终地址展示给用户。自有服务器每月 600GB 流量不作为安装包直链主预算。
4. 下载只接受 HTTPS 和受信任配置；必须校验配置签名、有效期、`environment`、`catalogRevision` 单调性、根文件夹集合、声明 ZIP 结构及批准 APK 的完整身份。版本、大小和 SHA-256 都是必须精确匹配的批准值。配置不能携带任意 shell、脚本、动态权限或任意包体 URL。当前长效配置使用 `2099-12-31T23:59:59.000Z`，客户端仍拒绝已过期值。
5. ZIP 完整下载并校验后才解压根目录唯一 APK；APK 所有批准字段匹配后才发布到公共 Download 和非流式推送。成功删除 ZIP，失败或取消按原生命周期清理私有临时文件。
6. 配置签名 / 修订回退、清单过期、源不可达或 APK 任一批准字段不符时拒绝并向用户给出可理解的下一步；不接受同版本不同包体，也不接受完整签名集合中的任意单个证书命中。

### Debug 真实组件验证边界

1. Debug 变体只持有 staging 配置根，Release 只持有 production 配置根。APP 身份来自各环境 V5 签名目录，源码不再内置真实组件发布者信任表。
2. Debug 与 Release 共用下载、ZIP 校验、受控解压、APK 核验、已选组件安装、回读和本地强类型授权主链。实际 03桌面在当前批次时才验证其启动和必要服务；其它应用按自身声明核验，合法空授权计划成功。远端不能开启跳过文件核验或伪造成功的模式。
3. Release 变体不读取 Debug profile；正式 Cloud profile、公钥或对象缺失时保持 fail closed。远端清单、蓝奏云链接和用户输入都不能把 Debug 资料带入 Release。
4. Debug ZIP 仍是外部不可信输入：归档根目录必须只有一个清单指定 APK，不接受 `__MACOSX`、目录或第二个 entry；每次更换 ZIP 都必须重新核验传输大小 / 摘要，并重新读取包名、目标版本与发布者证书身份，版本不匹配时不得进入安装。

### 蓝奏云 ZIP 特殊边界

1. 密码根文件夹地址指向网页，不等于任何 ZIP 对象地址；客户端在安装进度页背后用 Android System WebView 完成密码验证、枚举和当次文件下载回调，再交给应用自有原生下载器，不手工复刻隐藏字段或依赖第三方服务。
2. WebView 使用默认手机端标识，不改成桌面 User-Agent；不暴露应用 JavaScript bridge、设备文件或 ADB 能力。解析超时、未触发下载、最终响应为 HTML / JSON 或域名不在适配器允许范围时，立即终止本次配置加载并清理临时上下文。
3. 根文件夹不设业务 APP 数量上限，只受 payload 和字段长度约束。只处理启用声明，未声明文件忽略；缓存未命中才需要对应 ZIP。HTTPS、大小、超时、取消、根目录单 APK 与批准身份核验共用既有适配器；单应用失败隔离，任意确认已安装应用可进入维护。
4. 页面验证后产生的 `zipN.webgetstore.com` 地址、Cookie 和 Referer 只在内存中交给原生下载器；不写入配置、持久缓存、日志或诊断。页面改版、限流或密码错误只应形成结构化配置失败，不能降级为未校验来源。

## 3. ADB 与系统授权

1. ADB 命令使用版本化白名单和参数 schema，Cloud V5 不下发 deviceSetup、任意 shell 或动态设置名。授权由客户端已实现的强类型能力和实际 APK 声明生成。
2. 写入系统设置前读取原值，按白名单幂等追加，执行后回读并比较；未知值不覆盖，失败不静默，不删除车机已有通知或无障碍服务授权。
3. 首次连接前不承诺自动打开无线调试。当前样本 `S56_HQX` 为 Android 9、TCP `5555` 常驻开放且 `ro.adb.secure=0`，仅作为已测设备事实，不能当作通用安全或兼容承诺。
4. 新增 Android 权限、无障碍服务、文件访问或网络域名必须记录用户价值、版本边界、最小权限、拒绝后的功能退化和验证方式，不能因为“安装更方便”无限扩大权限。当前声明 `android.permission.INTERNET` 用于清单、固定来源 HTTPS 对象流和用户主动发起的局域网 TCP ADB 身份探测；仅在 Android 9 及以下申请 `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE`，用于读取和写入用户公共 `Download`，Android 10 及以上通过 `MediaStore.Downloads` 发布和扫描，不申请全盘管理权限。`android.permission.REQUEST_INSTALL_PACKAGES` 仅用于 `03helper` 自身更新调用系统安装器，受 Android O+“允许安装未知应用”用户授权约束；用户拒绝时必须保留结构化失败、重试和系统设置入口，不得借此浏览或静默安装任意第三方 APK。其它权限拒绝时保留应用运行并把公共 APK 复用降级为不可用，不能伪造命中。

5. 维护应用管理只接受 03桌面协议 v2 只读桥接返回的当前用户非系统应用完整批次；协议版本、summary 数量、连续行号、字段、重复包和 SHA-256 收据任一异常时整批拒绝。桥接只提供包名、显示名、版本、安装 / 更新时间、UID、launcher 与按包名读取的图标，不提供启动、停止、清数据、卸载或授权命令；应用动作必须重新绑定当前库存中的同一 `packageName`。

6. 应用行的设备操作只允许用户主动触发的六种固定 typed action：`START`、`FORCE_STOP`、`CLEAR_DATA`、`AUTHORIZE`、`UNINSTALL`、`DETAILS`。启动只使用桥接确认的本包 launcher，强停 / 清数据 / 卸载只绑定目标包名，清数据与卸载必须二次确认并回读；详情只返回结构化包元数据。一键授权只在 `1..128 MiB` 的目标 APK 声明读取门禁内生成危险运行时权限、固定 AppOp、无障碍与通知监听服务的类型化动作，每项均先读、写入、回读且单项失败继续；普通 / 签名权限只展示，不计入自动授权成功率。仍不接受任意 shell、远端命令、设置名或用户输入路径。

7. F3 的 TCP ADB 协议层固定复用 Apache-2.0 `dev.mobile:dadb:1.2.9`；发现与连接只读取固定设备身份，设备动作阶段只通过项目白名单网关执行固定推送路径、安装、身份回读、授权和可用性命令。库的 root 或任意 shell API 不向应用层、UI、清单或用户输入暴露。
8. 授权声明校验位于安装身份核验之后、任何 app-op 或 secure settings 写入之前；声明缺失时保留“已安装”证据并安全停止授权。Android 9 先读取现有安全列表并做条目 / 序列化容量预检，写入后回读且保留既有条目。部分授权动作失败时不得伪造整批授权成功。
9. 安装阶段不得启动任何目标应用；全部选定组件安装并完成安装证据后，按签名 `apps[]` 动态生成一次版本化授权计划，运行验证只允许启动 03 桌面。

## 4. 数据与日志

1. 只收集完成安装与用户主动维护所需的最少设备信息；不读取媒体、通讯录、车辆控制数据或应用数据内容。管理页会话内只保留当前非系统应用的包名、显示名、版本、安装 / 更新时间、launcher、图标和 UID 观测；第三方实时库存、授权条目与动作进度不写入持久化维护基线。
2. 日志只记录阶段、错误类别、非敏感设备标识和版本；诊断导出由用户主动触发并默认脱敏。
3. 不保存完整 shell 历史、私钥或可重放的授权令牌；ZIP、分片、解压中的 APK 和 MediaStore 临时读取副本按生命周期清理，不得在应用私有目录保留完整 APK；已校验 APK 只保留在公共 `Download`，一键清理只删除助手生成的 `03helper-` 文件。全量应用观测不写入可替代实时证据的持久化结论，冷启动后必须重新读取 03桌面桥接库存。

## 5. 高风险动作

清除数据、卸载、降级、重启、修改签名、发布、切换生产下载源和公开切换版本清单都必须取得用户当次明确授权；普通 debug 安装和最简 smoke 不自动扩大到这些动作。

## 6. 发布阻断

1. 四个 03 APP 与 Fossify 车机适配版的 production APK / ZIP、独立签名和本地台账已经核验，不再以 Debug 身份进入正式候选。
2. Fossify 仍是 GPLv3 第三方开源组件；公开提供修改版二进制时必须同时提供固定上游提交、完整补丁和许可证入口，不得声称 Fossify 官方签名或发布身份。
3. 当前剩余 production 阻断是：真实蓝奏入口、所声明 APP 的 ZIP 上传与文件完整性、Logo 公网对象、线上候选 smoke 和用户“上线”授权。revision 5 占位候选保持 `local-only` / `publishable=false`，不得直接写入线上配置。
