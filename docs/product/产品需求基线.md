# 03helper 产品需求基线

## 1. 产品定位

> 现行分发口径：Cloud V5 签名配置决定应用和批准的 APK 身份；选择页显示规范化版本与体积。公共缓存和下载 APK 的包名、完整当前证书集合、versionCode、versionName、字节数及 SHA-256 必须全部精确匹配。详见 `docs/protocols/android-helper-config-contract.md`。

1. 目标用户是需要在手机上把受信任的车机应用安装到目标设备的普通车主或维护人员。
2. “03应用安装助手”是独立的手机 Android 应用，不并入 03 歌词或 03桌面；后两者仍由各自产品仓库负责业务实现、包身份和正式发布。
3. 产品首要结果是让用户只在连接设备和选择应用组合时主动操作；连接成功后先快速读取并展示应用列表，用户点击“开始下载并安装”后才开始下载、校验和安装，其余步骤由助手自动完成并给出可理解的结果。
4. 安装成功后，产品从“首次安装向导”切换到“维护工具”。分发、重装和“安装推荐应用”继续只面向 Cloud 批准组件；“管理已安装应用”以当前用户已安装的全部非系统应用为独立管理范围，并在单个应用内提供按实际声明执行的一键授权。“修复授权”不再作为独立维护入口。

## 2. 首次安装路径

1. 用户只需安装助手本体，再从云端当前下载清单中选择应用；清单决定应用名称、启停、顺序和必选项。新增第三方应用无需升级助手，文件通过校验后才安装。安装包继续按需从蓝奏目录获取。
2. 选择页直接显示云端应用版本与体积。用户确认后先复用完全匹配本次批准记录的本地 APK，再下载未命中的文件；文件错误只影响对应应用。密码和下载上下文不出现在用户界面。
3. 每个 APP 使用单组件 ZIP，根目录只放一个 APK，禁止子目录和额外文件。缺失、下载或核验失败记录到该应用，剩余应用继续。必选项由云端决定，客户端不固定桌面必装；完成后统一展示结果。
4. 第 1 步：助手在手机靠近车机时优先进行有界的局域网发现；用户选择设备后必须完成真实 ADB 连接并保持到初始化和维护态，自动记录已确认的设备；OTG 只在独立实证通过后评审，当前不进入正式主链。
5. 第 2 步：按云端必装与可选策略选择应用，可选项默认选中且可取消；每行显示图标、名称、版本和体积，兼容性留在内部校验。
6. 第 3 至 5 步在用户确认后自动完成：先检查手机公共 `Download` 目录中是否已有通过身份和签名目标版本校验的 APK；未命中时在应用私有缓存中下载并校验 ZIP、解压唯一 APK、校验 APK 后发布到公共 `Download`。进度页固定展示“获取安装包、检查安装包、发送到车机、车机上安装、授权、检查是否可用”六个阶段；当前阶段始终显示线性进度条和百分比数字，不显示逐应用进度列表。能够计算时使用真实字节或真实完成比例；无法连续计算时只在当前真实阶段内平滑预测，`1.6s` 到 `70%`、`4.8s` 到 `90%`，随后缓慢逼近且不超过 `96%`，只有对应阶段的真实完成事件可以显示 `100%`。单个应用失败记录原因并跳过，剩余应用继续；全部安装身份回读后，从车机实际安装 APK 的原始 `AndroidManifest.xml` 读取每个目标包的声明，再用当前系统危险权限能力表和本地有限白名单筛选，编译一次版本化授权计划并逐项回读。普通权限、签名权限和当前车机不支持的未来权限不展示、不写入也不计入成功率。只启动 03 桌面并验证其进程 / 必要服务，其他已选组件只做安装存在性核验，最后展示完整或部分失败结果。
7. 第 6 步：首次成功后开放维护模式。应用分组固定为“管理已安装应用 / 安装推荐应用 / 安装本机应用”；常用分组保留检查更新，不再提供重复的一键“修复授权”入口。缓存清理、脱敏诊断及应用管理内的受控卸载继续按风险边界提供，破坏性操作必须单独确认。
8. 连接后的首次库存只按当前已验签 `apps[].packageName` 与组件 ID 交叉匹配。Release 清单只识别正式包名，车机已有的 staging / Debug 测试包不算已安装，仍允许安装正式包；staging / Debug 清单只识别测试包名。历史包名和别名不参与受控库存、更新或授权判断。
9. 清单和库存都读取成功、仍有未安装组件时，选择页在“开始下载并安装”下方提供“稍后安装”。点击后不下载、不安装、不授权，直接进入维护首页；该选择持久化，冷启动仍进入维护首页。已全部安装或清单 / 库存失败时不提供该动作。

## 3. V1 范围基线

1. 下载组件来自 Cloud 当前目录；标为必选的应用不可取消，不固定某个产品为必装组件。
2. 可选组件：03 歌词、文件管理器或其它经过审核的增强套件；具体清单、显示信息、排序、兼容范围和体积由签名 `apps[]` 与实际 APK 决定，不设业务层 APP 数量上限。
3. 连接方式：局域网发现 / ADB 为主；OTG 是否进入后续版本需完成手机、车机 USB 角色和 ADB USB 能力实证。
4. 自动步骤：解析下载页、优先复用公共 `Download` APK、下载与校验 ZIP、解压与校验 APK、发布并保留 APK、批量上传与安装、按目标包实际声明动态生成的一次版本化受控授权计划、仅启动 03 桌面进行快速可用性验证、结果展示和失败恢复。首次安装、更新、推荐应用安装与本机 APK 安装共用同一授权计划和回执校验 owner。
5. 维护动作：检查更新、保留数据重装、安装推荐应用、安装本机应用、管理当前用户的已安装非系统应用、缓存清理和诊断导出；检查更新按应用行逐项呈现，只有有更新的行可点击并单独启动一次更新，不提供“全部更新”；车机组件更新复用首次安装的下载、ZIP / APK 校验和设备安装主链。助手自更新在下载前检查 Android“安装未知应用”授权，未授权时先进入系统授权页，授权返回后才开始准备制品；下载与校验完成后自动进入 Android 系统安装器，并通过 `PackageManager` 回读确认，不再要求用户在进度页点击第二个安装按钮。管理页中的清除数据和卸载必须单独确认，降级和重启仍不提供。管理已安装应用中，只有由 03 桌面代理负责启动的第三方应用显示“开机启动”按钮；按钮布局与其它动作完全一致，状态只通过正式 power 图标的绿 / 红 / 灰颜色表达已设置、未设置、不可设置；03 桌面和 03 歌词由自身负责开机恢复，不进入代理启动列表。协议可用时弹窗标题保持不变，中间显示“开机后由03桌面代理启动此应用”和常见开关，保存期间只显示底部统一浮窗；协议缺失或不兼容时只显示“03桌面版本过低，请升级到最新版本。”；自启动状态批量读取，应用图标按身份缓存。
6. 视觉状态：首次安装全程使用浅蓝整屏背景与白色内容；安装成功后的维护态延续蓝色背景，并以大号、极简、按用途分组的按钮作为主要入口。进入应用管理后，应用本身不再分组，统一按安装时间倒序平铺。
7. 动效状态：页面进入 / 退出、按钮出现 / 消失 / 点击、加载、进度和结果切换全部使用短促的基础非线性动画，不允许静态突变。

## 4. 非目标

1. 不复制 03 歌词、03桌面或第三方组件的业务实现。
2. 不提供默认任意 ADB shell、无障碍模拟操作、车辆控制或后台常驻服务。
3. 不承诺在首次连接前自动打开无线调试；当前已知设备能力不能外推到所有车机固件。
4. 不接入第三方“直链转换器”、任意网盘脚本或运行时临时源；蓝奏云只通过安装助手自己的隐藏 WebView 适配器访问签名配置指定的密码根文件夹，不跳转外部浏览器，也不向用户展示网盘页面。
5. 不在首次安装流程中展示无关的通用 ADB 工具集合。

## 5. 验收口径

1. 用户能看到当前设备、已选组件、每一步状态、失败原因和下一步动作。
2. 成功结果必须有所有已选组件的安装证据、车机实际安装 APK 原始 Manifest 生成的精确授权计划及对应回读证据；仅当前批次安装实际 03桌面时要求其启动、进程及必要服务证据。Manifest 已解析且没有可自动处理声明时，零动作计划必须直接成功，不能只依据单条安装命令返回值，也不能把空计划显示为声明读取失败。
3. 中断或断线后能从最近可靠检查点恢复，已成功步骤不会被无意义地重复破坏。
4. 所有可见文案按使用者任务组织，不要求用户理解内部协议、包名或 shell 语法。
5. 首次安装按云端策略显示“必装”或可取消的“可选”，可选应用默认选中。每行显示名称、图标、版本和体积；未知应用先用通用图标，核验后用 APK 图标。不展示协议、ZIP 路径、目录密码或内部校验细节。
6. 签名、字段或根目录验证失败时拒绝本次加载；未声明文件忽略。声明 ZIP 缺失时可先尝试本地匹配 APK，本地与远端均不可用才标记该 APP 失败。其它 APP 继续，任意确认已安装应用可进入维护。
7. 授权弹窗只列出该应用实际声明且当前车机可自动处理的项目。没有可自动授权项时只显示右下角“知道了”；存在可授权项时显示“取消 / 一键授权”；授权动作结束后弹窗保持打开并只显示“完成”，由用户确认后关闭。授权成功必须有“读取原值、幂等追加、回读一致”的证据；已有通知或无障碍授权不能被覆盖，未声明或不可自动处理的权限不能制造“部分成功”。底部动作通知必须位于所有业务弹窗及其半透明遮罩之上。
8. 首次安装和维护首页都必须保持蓝底白字，不得在成功后切换成白底工具列表；维护动作必须通过大号分类按钮呈现。检查更新页只突出有更新的应用行，点击后只处理该目标，不能把其它应用混入本次结果。
9. 页面、按钮、加载、进度和结果状态的进入、退出与点击反馈均必须可观察到非线性动效；缺少动效即不满足 V1 体验验收。
10. 维护态“管理已安装应用”通过已安装 03桌面的版本化只读桥接读取全部非系统应用并按首次安装时间倒序展示。展开态仅对代理可管理的第三方应用显示“开机启动”，显示已设置自启动、未设置自启动或不可设置自启动；前两态点击后反向切换并以 03桌面代理回读为准，第三态置灰。按钮沿用普通动作的 icon + 文案布局，不附加小圆点或额外占位；三态只改变 power icon 颜色。03 桌面和 03 歌词不显示该代理动作，也不进入代理启动列表。检测不到 03桌面时只在管理页内提示“此功能依赖03桌面：请先在车机上安装03桌面”；管理页可用但自启动协议版本不匹配时，点击按钮的弹窗只显示“03桌面版本过低，请升级到最新版本。”，不得重复依赖说明。其它应用操作和授权、日志导出边界保持不变。
11. “安装本机应用”必须调用 Android 系统文件选择器，由用户明确选择一个 APK。助手立即把 `content://` 内容复制到单次私有工作区，限制为 `1 byte..1 GiB`，校验完整包名、版本、完整当前证书集合、SHA-256、最低 Android 版本并拒绝 split APK；安装后进入同一自动授权链。用户原文件永不删除，私有副本在成功、失败或取消后清理；该 APK 不写入 Cloud 推荐目录或长期维护基线。
12. 初始化安装、安装推荐应用和安装本机应用必须共用同一阶段账本、设备安装协调器和六阶段呈现组件。每个阶段按本批次所选应用聚合且百分比单调不回退；真实阶段快速完成时，尚未呈现的完成阶段至少展示 `360ms`，最终 `100%` 保留 `320ms` 后再进入成功结果。失败、暂停或断线立即进入对应结果 / 恢复状态，不得为了补动画延迟错误反馈；窄屏自动滚动到当前阶段。

## 6. 已确认事实与待确认项

### 已确认的方案事实

1. 当前目标车机实测为 `S56_HQX`、Android 9，TCP `5555` 常驻开放，`ro.adb.secure=0`；这些是当前样本事实，不是所有车机的兼容承诺。
2. 首次连接前不承诺由助手自动打开无线调试；当前固件无需额外开启即可评估局域网 ADB 主链。
3. 只有在手机本地完成 ZIP 校验、APK 解压和 APK 身份校验后，APK 才采用非流式推送；远端清单不得下发任意 shell 命令。

### 仍需完成的决策和证据

1. 客户端 V5 协议、云端批准身份核验、动态选择、单项失败与维护恢复已实现；本轮环境部署和数据转换由 Windows 开发机完成。真实下载与车机验收按验证矩阵执行，本地单测不能替代。
2. 目标车机固件上的局域网发现边界、设备唯一标识和断线恢复行为仍需运行级验证；OTG 仍未证明可行。
3. 正式授权动作、包签名信任链和发布节奏仍需逐项确认。
4. 四个 03 APP 与 Fossify 车机适配版已具备独立 production 签名和已核验 APK / ZIP。Fossify 保持第三方开源身份与原包名，公开分发必须同时提供固定上游提交、补丁和 GPLv3 许可证入口；真实蓝奏入口、文件完整性、Logo 对象、线上 smoke 与用户上线授权仍是首版发布阻断。

### 国内分发调研结论

1. 免费蓝奏云在安卓手机端直接下载 APK 会提示限制；用户已于 `2026-08-18` 在真实安卓手机上验证 ZIP 分享页可以正常进入、下载并由手机解压，流程无需登录。
2. 主源顺序为：读取云端签名配置、展示清单、用户选择、优先复用匹配本地 APK、按需下载声明 ZIP、核验 APK、安装。客户端只读取 V5，不维护另一套发布者清单。
3. 安装助手使用 Android System WebView 的默认手机端标识，不伪装桌面设备；WebView 只在安装进度页背后运行，用户不会看到外部浏览器、蓝奏云页面、ZIP 文件或解压界面。
4. 既有 ZIP 与手机体验保留为来源证据；每次新发布必须核验实际文件与签名配置一致。真实 Android System WebView 和车机安装结果单独记录。
