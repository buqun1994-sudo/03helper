# 03helper 产品需求基线

## 1. 产品定位

1. 目标用户是需要在手机上把受信任的车机应用安装到目标设备的普通车主或维护人员。
2. “03应用安装助手”是独立的手机 Android 应用，不并入 03 歌词或 03桌面；后两者仍由各自产品仓库负责业务实现、包身份和正式发布。
3. 产品首要结果是让用户只在连接设备和选择 APK 组合时主动操作；“开始安装”属于组件选择页的最终确认，其余步骤由助手自动完成并给出可理解的结果。
4. 安装成功后，产品从“首次安装向导”切换到“维护工具”，但维护动作仍受白名单、风险分级和用户授权约束。

## 2. 首次安装路径

1. 前置分发采用“只安装助手本体”的主方案：助手启动后再按签名版本清单下载零三组件的单组件 ZIP。这样可以集中修复安装流程、避免用户预先整理多份 APK，也不把本项目自有服务器 600GB/月流量用于安装包直链主分发。
2. 组件下载采用签名版本清单和固定源策略：每个组件使用一个无密码蓝奏云 ZIP 分享链接作为国内自动主源，Cloudflare R2 是第一自动备用，GitHub Releases 是第二自动备用；三个自动来源镜像同一 ZIP，密码聚合文件夹、三应用合并 ZIP 和夸克只作人工或离线兜底。
3. 第 1 步：助手在手机靠近车机时优先进行有界的局域网发现并连接设备，自动记录已确认的设备；OTG 只在独立实证通过后评审，当前不进入正式主链。
4. 第 2 步：用户选择 APK 组合。03 歌词和 03桌面默认选中且不可取消；文件管理器作为可选增强套件。
5. 第 3 至 5 步自动完成：在应用内隐藏加载蓝奏云手机页面、下载并校验 ZIP、解压唯一 APK、校验 APK 后删除 ZIP、向车机非流式推送并安装、执行受控白名单授权、启动目标应用并快速验证可用性，最后展示安装 / 授权 / 可用性结果。
6. 第 6 步：首次成功后开放维护模式，提供检查更新、保留数据重装、修复授权、重启服务、缓存清理、受控安装 / 卸载和脱敏诊断等入口；破坏性操作必须单独确认。

## 3. V1 范围基线

1. 核心组件：03 歌词和 03桌面；首次安装流程中不可取消。
2. 可选组件：文件管理器或其它经过审核的增强套件；具体清单、兼容范围和体积由签名版本清单决定。
3. 连接方式：局域网发现 / ADB 为主；OTG 是否进入后续版本需完成手机、车机 USB 角色和 ADB USB 能力实证。
4. 自动步骤：解析下载页、下载与校验 ZIP、解压与校验 APK、删除 ZIP、上传、安装、受控授权、快速可用性验证、结果展示和失败恢复。
5. 维护动作：检查更新、保留数据重装、修复授权、安装 / 卸载受控组件、缓存清理和诊断导出；清理数据、卸载、降级和重启等破坏性动作必须单独确认。
6. 视觉状态：首次安装全程使用浅蓝整屏背景与白色内容；安装成功后的维护态延续蓝色背景，并以大号、极简、按用途分组的按钮作为主要入口。
7. 动效状态：页面进入 / 退出、按钮出现 / 消失 / 点击、加载、进度和结果切换全部使用短促的基础非线性动画，不允许静态突变。

## 4. 非目标

1. 不复制 03 歌词、03桌面或第三方组件的业务实现。
2. 不提供默认任意 ADB shell、无障碍模拟操作、车辆控制或后台常驻服务。
3. 不承诺在首次连接前自动打开无线调试；当前已知设备能力不能外推到所有车机固件。
4. 不接入第三方“直链转换器”、任意网盘脚本或运行时临时源；蓝奏云只通过安装助手自己的隐藏 WebView 适配器访问清单中固定的无密码单组件 ZIP 官方分享地址，不跳转外部浏览器，也不向用户展示网盘页面。
5. 不在首次安装流程中展示无关的通用 ADB 工具集合。

## 5. 验收口径

1. 用户能看到当前设备、已选组件、每一步状态、失败原因和下一步动作。
2. 成功结果必须同时有安装、授权和可用性证据，不能只依据单条命令返回值。
3. 中断或断线后能从最近可靠检查点恢复，已成功步骤不会被无意义地重复破坏。
4. 所有可见文案按使用者任务组织，不要求用户理解内部协议、包名或 shell 语法。
5. 首次安装页面将 03 歌词和 03桌面锁定为必装，并允许用户明确看到文件管理器的可选状态、预计下载体积和兼容范围；不展示蓝奏云、R2、GitHub、ZIP 路径或解压细节。
6. 下载、解压或校验失败时，助手按固定顺序从蓝奏云单组件 ZIP 分享页切换到 R2，再切换到 GitHub Releases；任一阶段失败都要记录结构化原因，全部失败后给出可理解的下一步，不暗示 APK 已安装。
7. 授权成功必须有“读取原值、幂等追加、回读一致”的证据；已有通知或无障碍授权不能被覆盖。
8. 首次安装和维护首页都必须保持蓝底白字，不得在成功后切换成白底工具列表；维护动作必须通过大号分类按钮呈现。
9. 页面、按钮、加载、进度和结果状态的进入、退出与点击反馈均必须可观察到非线性动效；缺少动效即不满足 V1 体验验收。

## 6. 已确认事实与待确认项

### 已确认的方案事实

1. 当前目标车机实测为 `S56_HQX`、Android 9，TCP `5555` 常驻开放，`ro.adb.secure=0`；这些是当前样本事实，不是所有车机的兼容承诺。
2. 首次连接前不承诺由助手自动打开无线调试；当前固件无需额外开启即可评估局域网 ADB 主链。
3. 只有在手机本地完成 ZIP 校验、APK 解压和 APK 身份校验后，APK 才采用非流式推送；远端清单不得下发任意 shell 命令。

### 仍需完成的决策和证据

1. 蓝奏云隐藏 WebView 适配器、ZIP 下载与解压器、Cloudflare R2 对外对象、GitHub Releases、缓存策略、Android 组件清单与回滚流程尚未接入实现；Cloud 现有 release index 可作为控制面能力，Android ZIP profile 仍需单独施工。
2. 目标车机固件上的局域网发现边界、设备唯一标识和断线恢复行为仍需运行级验证；OTG 仍未证明可行。
3. 正式授权动作、包签名信任链和发布节奏仍需逐项确认。
4. 03桌面尚无长期 Release 签名；03 歌词尚未建立 production 发布身份；文件管理器仍是 Debug 身份，正式分发还需履行 GPL 义务。这三项是发布阻断，不得在首版上线前绕过。

### 国内分发调研结论

1. 免费蓝奏云在安卓手机端直接下载 APK 会提示限制；用户已于 `2026-08-18` 在真实安卓手机上验证无密码 ZIP 分享页可以正常进入、下载并由手机解压，流程无需登录。
2. 正式采用“每个组件一个无密码 ZIP 分享页 → 安装助手内隐藏 Android WebView 执行手机页面 → 原生下载器获取 ZIP → 校验 ZIP → 解压唯一 APK → 校验 APK → 删除 ZIP”的路径作为国内自动主源；R2 和 GitHub Releases 镜像同一 ZIP 并自动兜底。
3. 安装助手使用 Android System WebView 的默认手机端标识，不伪装桌面设备；WebView 只在安装进度页背后运行，用户不会看到外部浏览器、蓝奏云页面、ZIP 文件或解压界面。
4. 用户提供的三个 ZIP 测试分享页已经进入施工输入，但组件映射与发布元数据仍需在清单冻结时确认；剩余网络门槛只验证安装助手内的隐藏 WebView 下载回调、真实 ZIP 字节和自动解压闭环，不再重复论证人工手机 ZIP 下载是否可行。
