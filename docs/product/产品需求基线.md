# 03helper 产品需求基线

## 1. 产品定位

> 现行版本字段口径：Cloud `apps[]` 为每个应用提供 `versionCode`、`versionName`、`apkSizeBytes`；选择页直接显示规范化的 `V1.2.3` 与 `2.6M`。`catalogVersion` 只用于内部配置修订，不能作为应用版本。

1. 目标用户是需要在手机上把受信任的车机应用安装到目标设备的普通车主或维护人员。
2. “03应用安装助手”是独立的手机 Android 应用，不并入 03 歌词或 03桌面；后两者仍由各自产品仓库负责业务实现、包身份和正式发布。
3. 产品首要结果是让用户只在连接设备和选择应用组合时主动操作；连接成功后先快速读取并展示应用列表，用户点击“开始下载并安装”后才开始下载、校验和安装，其余步骤由助手自动完成并给出可理解的结果。
4. 安装成功后，产品从“首次安装向导”切换到“维护工具”，但维护动作仍受白名单、风险分级和用户授权约束。

## 2. 首次安装路径

1. 前置分发采用“只安装助手本体”的主方案：助手启动后只接受 Cloud schema V3 签名配置，从中取得一个受保护的蓝奏根文件夹和动态 `apps[]` 目录声明。配置统一描述应用名称、描述、启用状态、安装策略、排序、客户端能力门槛和受限 typed `deviceSetup`；不要求用户预先整理多份 APK，也不把本项目自有服务器 600GB/月流量用于安装包直链主分发。
2. Cloud 签名 `apps[]` 是选择页的展示控制面：每个启用条目直接提供 `versionCode`、`versionName`、`apkSizeBytes`，客户端显示规范化的 `V1.2.3`、`2.6M`；`catalogVersion` 只用于配置修订和防回滚。客户端仍按声明文件名枚举根目录，未声明文件直接忽略，但远端 ZIP 缺失不再单独阻断首次安装。用户确认后先检查手机公共 `Download` 中的匹配 APK，只有本地未命中时才解析对应远端 ZIP；实际 APK 的包名、版本、大小、SHA-256、最低 SDK 和证书仍由客户端读取并校验。密码文件夹不向用户展示，短时下载地址只在内存中使用。
3. 每个远端 APP 仍采用单组件 ZIP（一个 ZIP 只包含一个 APP 的 APK）：归档根目录只允许一个 APK，不接受多个 APK、子目录、说明文件或未知文件；声明 APP 的 ZIP 缺失、下载、解压或身份校验失败只记录该 APP，继续处理其它 APP。`desktop` 仍是唯一不可取消的核心必装项，但它失败也要走完整结果页，不得让安装流程停在中间。
4. 第 1 步：助手在手机靠近车机时优先进行有界的局域网发现；用户选择设备后必须完成真实 ADB 连接并保持到初始化和维护态，自动记录已确认的设备；OTG 只在独立实证通过后评审，当前不进入正式主链。
5. 第 2 步：用户选择应用组合。`desktop` 是唯一核心并默认选中且不可取消；其它启用 APP 按服务端排序动态呈现并可选。选择行显示本地 logo、名称、版本和体积，不展示“适用于当前车机”；兼容性只作为内部门禁。
6. 第 3 至 5 步在用户确认后自动完成：先检查手机公共 `Download` 目录中是否已有通过身份校验的目标 APK；未命中时在应用私有缓存中下载并校验 ZIP、解压唯一 APK、校验 APK 后发布到公共 `Download`。进度页只展示获取、检查、发送、授权、检查可用性五个稳定阶段及真实百分比，不显示逐应用进度列表。单个应用失败记录原因并跳过，剩余应用继续；完成后按签名 `apps[]` 动态生成并执行版本化受控白名单授权计划，只启动 03 桌面并验证其进程 / 必要服务，其他已选组件只做安装存在性核验，最后展示完整或部分失败结果。
7. 第 6 步：首次成功后开放维护模式，提供检查更新、保留数据重装、修复授权、重启服务、缓存清理、受控安装 / 卸载和脱敏诊断等入口；破坏性操作必须单独确认。

## 3. V1 范围基线

1. 核心组件：03 桌面；首次安装流程中不可取消。
2. 可选组件：03 歌词、文件管理器或其它经过审核的增强套件；具体清单、显示信息、排序、兼容范围和体积由签名 `apps[]` 与实际 APK 决定，不设业务层 APP 数量上限。
3. 连接方式：局域网发现 / ADB 为主；OTG 是否进入后续版本需完成手机、车机 USB 角色和 ADB USB 能力实证。
4. 自动步骤：解析下载页、优先复用公共 `Download` APK、下载与校验 ZIP、解压与校验 APK、发布并保留 APK、批量上传与安装、按 `apps[]` 动态生成的一次版本化受控授权计划、仅启动 03 桌面进行快速可用性验证、结果展示和失败恢复。
5. 维护动作：检查更新、保留数据重装、修复授权、安装 / 卸载受控组件、缓存清理和诊断导出；清理数据、卸载、降级和重启等破坏性动作必须单独确认。
6. 视觉状态：首次安装全程使用浅蓝整屏背景与白色内容；安装成功后的维护态延续蓝色背景，并以大号、极简、按用途分组的按钮作为主要入口。
7. 动效状态：页面进入 / 退出、按钮出现 / 消失 / 点击、加载、进度和结果切换全部使用短促的基础非线性动画，不允许静态突变。

## 4. 非目标

1. 不复制 03 歌词、03桌面或第三方组件的业务实现。
2. 不提供默认任意 ADB shell、无障碍模拟操作、车辆控制或后台常驻服务。
3. 不承诺在首次连接前自动打开无线调试；当前已知设备能力不能外推到所有车机固件。
4. 不接入第三方“直链转换器”、任意网盘脚本或运行时临时源；蓝奏云只通过安装助手自己的隐藏 WebView 适配器访问签名配置指定的密码根文件夹，不跳转外部浏览器，也不向用户展示网盘页面。
5. 不在首次安装流程中展示无关的通用 ADB 工具集合。

## 5. 验收口径

1. 用户能看到当前设备、已选组件、每一步状态、失败原因和下一步动作。
2. 成功结果必须同时有所有已选组件的安装证据、按 `apps[]` 生成的版本化授权计划回读证据、03 桌面启动 / 进程 / 必要服务证据以及其他已选组件的安装存在性证据，不能只依据单条命令返回值。
3. 中断或断线后能从最近可靠检查点恢复，已成功步骤不会被无意义地重复破坏。
4. 所有可见文案按使用者任务组织，不要求用户理解内部协议、包名或 shell 语法。
5. 首次安装页面将 `desktop` 锁定为必装，其它启用 APP 动态显示为可选，并在每行前置显示受信本地 APP logo，同时显示名称、简要版本和预计下载体积。兼容性只在内部会话 / 结果证据中做门禁，不展示“适用于当前车机”；云端描述、目录状态和错误原因也不塞进首次安装选择框；不展示蓝奏云、ZIP 路径或解压细节。`catalogVersion` 仅作内部修订号，历史版本不进入当前自动流程。
6. 配置签名、字段、根文件夹身份或密码验证失败时拒绝本次目录加载；未声明文件直接忽略。远端目录中缺少某个声明 ZIP（包括 `desktop`）时，仍先允许选择页展示云端字段并尝试公共 `Download`；本地和远端都不可用时只标记该 APP，绝不把它误报为可安装，也不阻断其它 APP。只有 `desktop` 最终有可用证据时结果页才提供进入维护的动作。
7. 授权成功必须有“读取原值、幂等追加、回读一致”的证据；已有通知或无障碍授权不能被覆盖。
8. 首次安装和维护首页都必须保持蓝底白字，不得在成功后切换成白底工具列表；维护动作必须通过大号分类按钮呈现。
9. 页面、按钮、加载、进度和结果状态的进入、退出与点击反馈均必须可观察到非线性动效；缺少动效即不满足 V1 体验验收。

## 6. 已确认事实与待确认项

### 已确认的方案事实

1. 当前目标车机实测为 `S56_HQX`、Android 9，TCP `5555` 常驻开放，`ro.adb.secure=0`；这些是当前样本事实，不是所有车机的兼容承诺。
2. 首次连接前不承诺由助手自动打开无线调试；当前固件无需额外开启即可评估局域网 ADB 主链。
3. 只有在手机本地完成 ZIP 校验、APK 解压和 APK 身份校验后，APK 才采用非流式推送；远端清单不得下发任意 shell 命令。

### 仍需完成的决策和证据

1. 客户端已完成本地 Android schema V3 签名 envelope、动态 `apps[]`、密码根文件夹隐藏 WebView、动态 ZIP 下载 / 解压 / APK 身份校验、官方发布者证书根和修订防回滚；Cloud Android distribution-config 公共 staging 当前仍需完成部署与人工联调。
2. 目标车机固件上的局域网发现边界、设备唯一标识和断线恢复行为仍需运行级验证；OTG 仍未证明可行。
3. 正式授权动作、包签名信任链和发布节奏仍需逐项确认。
4. 03桌面尚无长期 Release 签名；03 歌词尚未建立 production 发布身份；文件管理器仍是 Debug 身份，正式分发还需履行 GPL 义务。这三项是发布阻断，不得在首版上线前绕过。

### 国内分发调研结论

1. 免费蓝奏云在安卓手机端直接下载 APK 会提示限制；用户已于 `2026-08-18` 在真实安卓手机上验证 ZIP 分享页可以正常进入、下载并由手机解压，流程无需登录。
2. 正式采用“schema V3 签名配置下发密码根文件夹与动态 `apps[]` → 安装助手内隐藏 Android WebView 完成验证和枚举 → 原生下载器获取已声明 ZIP → 动态读取 APK 身份 → 安装”的路径作为当前主源；不依赖固定 APP 数量、固定索引或人工维护客户端链接。
3. 安装助手使用 Android System WebView 的默认手机端标识，不伪装桌面设备；WebView 只在安装进度页背后运行，用户不会看到外部浏览器、蓝奏云页面、ZIP 文件或解压界面。
4. 用户提供的 ZIP 测试分享页已经进入施工输入；三份历史映射只作为 Debug 验真夹具，当前客户端按签名 `apps[]` 动态处理并由本地官方发布者证书根校验，真实 Android System WebView、真实 ZIP 字节和自动解压闭环仍由用户人工主测，不重复论证已完成的人工手机 ZIP 下载体验。
